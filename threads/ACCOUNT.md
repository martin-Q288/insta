# 계정 세팅

새로 팔 인스타그램·스레드 계정의 이름, 핸들, 소개글. 그대로 쓰시면 됩니다.

기존 라스트 아더 계정은 공동구매 중개용이라 팔로워 관심사가 다릅니다.
같은 계정에 올리면 도달만 깎이고 그 계정도 같이 죽습니다. 새로 팝니다.

> **인스타 핸들은 대소문자를 구분하지 않습니다.** `AI_LoLo` 로 입력해도
> `ai_lolo` 로 저장되고 그렇게 표시됩니다. `AI_LoLo` 표기는 아래 **표시 이름**
> 칸에서 살아납니다 — 거기는 대문자가 그대로 유지됩니다.

| 순위 | 핸들 | 왜 |
|---|---|---|
| 1 | `ai_lolo` | 원안 그대로 |
| 2 | `ai.lolo` | 밑줄이 막혔을 때. 인스타는 마침표도 허용 |

넷 다 막혔으면 뒤에 두 글자를 붙이십시오. **숫자는 붙이지 마세요** —
`ai_lolo2` 같은 건 부계정이나 사칭 계정처럼 보입니다.

## 주어를 왜 이렇게 나눴나

이 계정 글은 **AI가 씁니다.** 숨길 이유가 없고, 숨기면 나중에 전부 무너집니다.
레퍼런스 사례에서도 사람들이 AI인 걸 알고 나서 오히려 관심을 가졌습니다.

그런데 그러면 **1인칭 주어를 정확히 써야 합니다.**

공동구매 중개, 통신판매업 신고, 스마트스토어 운영은 **사장님 경력이지 AI 경력이
아닙니다.** "제가 공동구매를 했고"라고 쓰면 그 순간 거짓말입니다.
그리고 이 계정이 가진 유일한 신뢰 근거가 그 경력이라서, 그게 무너지면 나머지
주장도 같이 의심받습니다.

그래서 이렇게 나눕니다.

| 주어 | 무엇 |
|---|---|
| 로로(AI) | 이 프로젝트에서 실제로 판 수량. 지금은 0 |
| 사장 | 공동구매 중개, 통신판매업 2021, 스마트스토어 운영 |

`config.json` 의 `product.persona` 가 이걸 강제합니다. 발행 글과 답글이 같은
규칙을 씁니다(`lib/persona.mjs`). 테스트가 1인칭 오용을 검사합니다.

## 계정 만든 뒤 순서

1. [ ] 인스타그램 계정 생성 → 스레드 연결
2. [ ] 표시 이름·소개글 채우기 (위 문안)
3. [ ] **라스트 아더 계정에서 새 계정을 한 번만 소개** — 전환율은 낮아도
       새 계정이 첫날부터 유령이 아니게 됩니다. 반복은 하지 마세요
4. [ ] `posts.md` 의 첫 2~3개는 **손으로** 올리기
5. [ ] `config.json` 의 `accountName` 과 `persona.name` 이 실제 계정과 같은지 확인
6. [ ] `npm run check` 통과
7. [ ] `npm run loop`

4번을 건너뛰지 마세요. 팔로워 0인 계정이 첫날부터 API로만 발행하는 건 굳이
만들 필요 없는 스팸 신호입니다.
