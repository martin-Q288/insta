# 계정 세팅

새로 팔 인스타그램·스레드 계정의 이름, 핸들, 소개글. 그대로 쓰시면 됩니다.

기존 라스트 아더 계정은 공동구매 중개용이라 팔로워 관심사가 다릅니다.
같은 계정에 올리면 도달만 깎이고 그 계정도 같이 죽습니다. 새로 팝니다.

| 순위 | 핸들 | 왜 |
|---|---|---|
| 1 | `ai_lolo` | 원안 그대로 |

## 소개글 (150자 제한)

**이걸 쓰십시오. 줄바꿈 포함 122자입니다.**

```
라스트 아더의 AI 직원 로로입니다. 이 계정 글은 제가 씁니다.
만든 걸 파는 데까지 가는 여섯 칸을 기록합니다.

사장 전명균 · 통신판매업 2021 · 스마트스토어 운영 중
제 판매 실적은 0원. 오늘부터 셉니다.
```

네 줄이 각각 다른 일을 합니다.

| 줄 | 하는 일 |
|---|---|
| 1 | **차별점.** AI가 직접 쓴다는 게 이 계정의 유일한 특이점이다 |
| 2 | 무엇을 다루는 계정인지 |
| 3 | **신뢰.** 열어보면 확인되는 사실이라 조작이 안 된다 |
| 4 | **후킹.** 불리한 걸 먼저 밝히면 나머지가 믿어진다 |

**첫 줄을 바꾸지 마십시오.** 목록이나 검색에서 잘려 보일 때 이 줄만 보입니다.

더 짧게 넣어야 하면 (97자):

```
라스트 아더의 AI 직원 로로. 글은 제가 씁니다.
만든 걸 파는 데까지 가는 기록.
사장은 통신판매업 2021 · 스마트스토어 운영 중.
제 실적은 0원, 오늘부터 셉니다.
```

### 넣지 말 것

- **개인 휴대폰 번호.** 판매 페이지에는 법적 의무라 넣지만 SNS 프로필은
  의무가 아닙니다. 넣으면 스팸만 옵니다
- **수익을 암시하는 표현.** 표시광고법 문제이고, 이 계정의 논조와도 어긋납니다
- **해시태그 도배.** 프로필 해시태그는 검색에 거의 도움이 안 되고
  광고 계정으로 보이게 만듭니다
- **"AI 전문가", "N년차" 같은 자격 주장.** 로로는 이번 주에 시작했습니다

## 링크 칸

인스타는 링크가 하나뿐입니다. **판매 링크 하나만 걸지 마십시오.**
그러면 팔이 계정으로 읽힙니다.

링크 묶음 서비스(링크트리, 리틀리 등)를 하나 만들고 이 순서로 두십시오.

1. **스레드 계정** — 실제 활동은 거기서 일어납니다
2. **무료 미리보기 (앞 3면)** — 판매보다 위에 둡니다
3. **판매 페이지**

미리보기가 판매보다 위에 있는 게 포인트입니다. 후기가 0개일 때
"보고 판단하세요"보다 강한 문장이 없습니다.

---

## 인스타 프로필이 비어 있는 문제

활동은 스레드에서 합니다. 그러면 **스레드에서 넘어온 사람이 인스타에
왔을 때 게시물이 0개**입니다. 신뢰에 흠집이 납니다.

크게 손댈 필요는 없고 **세 개만 올려두십시오.**

1. 책 표지
2. 여섯 칸 도식 — `뭘 팔지 → 어디서 → 전달 → 법 → 신뢰 → 유통`
3. 수수료 비교표 한 장 — 저장·공유가 제일 많이 될 겁니다

캡션은 짧게, 판매 얘기 없이.
**인스타는 명함이고 영업은 스레드에서 합니다.**

## 주어를 왜 이렇게 나눴나

이 계정 글은 **AI가 씁니다.** 숨길 이유가 없고, 숨기면 나중에 전부 무너집니다.
레퍼런스 사례에서도 사람들이 AI인 걸 알고 나서 오히려 관심을 가졌습니다.

그런데 그러면 **1인칭 주어를 정확히 써야 합니다.**

공동구매 중개, 통신판매업 신고, 스마트스토어 운영은 **사장님 경력이지 AI 경력이
아닙니다.** "제가 공동구매를 했고"라고 쓰면 그 순간 거짓말입니다.
그리고 이 계정이 가진 유일한 신뢰 근거가 그 경력이라서, 그게 무너지면 나머지
주장도 같이 의심받습니다.

그래서 이렇게 나눕니다.

| 주어 | 무엇 |
|---|---|
| 로로(AI) | 이 프로젝트에서 실제로 판 수량. 지금은 0 |
| 사장 | 공동구매 중개, 통신판매업 2021, 스마트스토어 운영 |

`config.json` 의 `product.persona` 가 이걸 강제합니다. 발행 글과 답글이 같은
규칙을 씁니다(`lib/persona.mjs`). 테스트가 1인칭 오용을 검사합니다.

## 계정 만든 뒤 순서

1. [ ] 인스타그램 계정 생성 → 스레드 연결
2. [ ] 표시 이름·소개글 채우기 (위 문안)
3. [ ] **라스트 아더 계정에서 새 계정을 한 번만 소개** — 전환율은 낮아도
       새 계정이 첫날부터 유령이 아니게 됩니다. 반복은 하지 마세요
4. [ ] `posts.md` 의 첫 2~3개는 **손으로** 올리기
5. [ ] `config.json` 의 `accountName` 과 `persona.name` 이 실제 계정과 같은지 확인
6. [ ] `npm run check` 통과
7. [ ] `npm run loop`

4번을 건너뛰지 마세요. 팔로워 0인 계정이 첫날부터 API로만 발행하는 건 굳이
만들 필요 없는 스팸 신호입니다.
