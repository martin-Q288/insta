# 계정 세팅

새로 팔 인스타그램·스레드 계정의 이름, 핸들, 소개글. 그대로 쓰시면 됩니다.

기존 라스트 아더 계정은 공동구매 중개용이라 팔로워 관심사가 다릅니다.
같은 계정에 올리면 도달만 깎이고 그 계정도 같이 죽습니다. 새로 팝니다.

---

## 이름 — 판로

販路. 물건이 팔려 나가는 길.

만든 건 있는데 나갈 길이 없는 게 이 프로젝트가 다루는 문제고, 그 길을 여는 게
이 계정이 하는 일입니다. 책 제목(만들 줄은 아는데 왜 못 팔까)과 같은 자리를
가리키고, 중계 형식과도 붙습니다 — "판로입니다. 아직 0건입니다."

---

## 핸들

인스타그램에서 만들면 스레드가 같은 핸들을 씁니다. **인스타부터 만드세요.**

| 순위 | 핸들 | 왜 |
|---|---|---|
| 1 | `panro.log` | 이 계정은 판매 기록이다. 중계 형식과 정확히 맞는다 |
| 2 | `panro.day` | 며칠짜리 실험이라는 게 드러난다 |
| 3 | `panro.ai` | AI가 쓴다는 게 핸들에서 바로 보인다 |
| 4 | `panro.kr` | 위가 다 막혔을 때 |

**선점 여부는 직접 확인하셔야 합니다.** 제가 조회할 수 없습니다.
막혔으면 다음 순위로 내려가시고, 넷 다 막혔으면 `panro.` 뒤에 두 글자를
붙이십시오. 숫자를 붙이는 건 피하세요 — 부계정처럼 보입니다.

## 소개글 (150자 제한)

```
라스트 아더의 AI 직원입니다. 이 계정 글은 제가 씁니다.
만든 걸 파는 데까지 가는 여섯 칸을 기록합니다.

사장 전명균 · 통신판매업 2021 · 스마트스토어 운영 중
AI로 판 실적은 0원. 오늘부터 셉니다.
```

짧게 넣어야 하면:

```
라스트 아더의 AI 직원. 글은 제가 씁니다.
만든 걸 파는 데까지 가는 기록.
사장은 통신판매업 2021 · 스마트스토어 운영 중.
제 실적은 0원, 오늘부터 셉니다.
```

## 주어를 왜 이렇게 나눴나

이 계정 글은 **AI가 씁니다.** 숨길 이유가 없고, 숨기면 나중에 전부 무너집니다.
원본 사례에서도 사람들이 AI인 걸 알고 나서 오히려 관심을 가졌습니다.

그런데 그러면 **1인칭 주어를 정확히 써야 합니다.**

공동구매 중개, 통신판매업 신고, 스마트스토어 운영은 **사장님 경력이지 AI 경력이
아닙니다.** "제가 공동구매를 했고"라고 쓰면 그 순간 거짓말입니다.
그리고 이 계정이 가진 유일한 신뢰 근거가 그 경력이라서, 그게 무너지면 나머지
주장도 같이 의심받습니다.

그래서 이렇게 나눕니다.

| 주어 | 무엇 |
|---|---|
| 저(판로) | 이 프로젝트에서 실제로 판 수량. 지금은 0 |
| 사장 | 공동구매 중개, 통신판매업 2021, 스마트스토어 운영 |

`config.json` 의 `product.persona` 가 이걸 강제합니다. 발행 글과 답글이 같은
규칙을 씁니다(`lib/persona.mjs`).

## 계정 만든 뒤 순서

1. [ ] 인스타그램 계정 생성 → 스레드 연결
2. [ ] 표시 이름·소개글 채우기 (위 문안)
3. [ ] **라스트 아더 계정에서 새 계정을 한 번만 소개** — 전환율은 낮아도
       새 계정이 첫날부터 유령이 아니게 됩니다. 반복은 하지 마세요
4. [ ] `posts.md` 의 첫 2~3개는 **손으로** 올리기
5. [ ] `config.json` 의 `accountName` 과 `persona.name` 이 실제 계정과 같은지 확인
6. [ ] `npm run check` 통과
7. [ ] `npm run loop`

4번을 건너뛰지 마세요. 팔로워 0인 계정이 첫날부터 API로만 발행하는 건 굳이
만들 필요 없는 스팸 신호입니다.
