# AI 활용할 줄은 아는데 어떻게 수익화 할까

네 가지 수익 모델과 첫 매출까지의 실행 순서

---

## 이 자료가 다루는 범위

AI를 다룰 줄은 압니다. 프롬프트도 짜고, 자동화도 붙여보고, 결과물도 만들어 봤습니다.
그런데 매출은 0입니다.

원인은 스킬이 아닙니다. **수익 모델을 정하지 않았기 때문입니다.**

"AI로 무엇을 할 수 있는가"와 "누가 나에게 비용을 지불하는가"는 다른 질문입니다.
전자는 기술 영역이고 후자는 상품 영역인데, 대부분 전자만 계속 파고듭니다.
도구가 늘어도 통장이 그대로인 이유가 여기 있습니다.

| 다루는 것 | 다루지 않는 것 |
|---|---|
| 수익 모델 4종과 **실제 시장 단가** | AI 도구 사용법 (다룰 줄 안다는 전제) |
| 내 조건에 맞는 모델 선택 기준 | 코딩 교육 |
| 아이템 발굴과 시장 검증 | 유료 광고 집행 |
| **견적 산정과 범위 합의** | 법률·세무 자문 (실무 정리까지) |
| 첫 문의부터 입금까지의 프로세스 | |
| 리드 확보 · 가격 정책 · 레퍼런스 0 대응 | |
| 결제 채널 · 납품 · 법무 | |

**수치는 전부 확인해서 넣었습니다.** 카테고리별 실제 등록 단가, 플랫폼 수수료율,
통신판매업 면제 기준 조항까지. 추정치는 넣지 않았고, 확인 시점과 확인 경로를
부록 C에 정리했습니다.

목차를 보시고 이미 아는 내용이면 여기서 덮으셔도 됩니다.

---

## 1. 수익 모델 4종

AI 수익화는 다양해 보이지만 구조는 넷입니다. 그리고 **넷은 서로 다른 사업**입니다.
단가, 리드타임, 확장 방식이 전부 다릅니다.

### ① 제품 판매

전자책, 템플릿, 프롬프트 팩, 노션 서식, GPTs, 스크립트.
한 번 만들어 반복 판매합니다.

- **단가** — 크몽 기준 최저 5,000원부터 등록됩니다. 전자책·템플릿류는
  1만~5만원대가 주력이고 그 이상은 저항이 큽니다
- **리드타임** — 며칠. 제작 후 등록하면 당일 매출이 발생할 수도 있습니다
- **확장** — 수량. 판매량이 늘어도 원가가 거의 안 늘어납니다
- **한계** — **객단가가 낮아 볼륨이 필요합니다.** 3만원 상품으로 300만원을
  만들려면 100건이고, 100건은 트래픽 없이 안 나옵니다

### ② 제작 대행

클라이언트 업무를 자동화하거나 도구를 구축해 줍니다.

- **단가** — 업무 자동화·매크로 제작이 **평균 20만원 수준**입니다.
  단순 엑셀 자동화는 15만원부터, 파이썬 기반 데이터 수집이나 API 연동이
  들어가면 **30만~100만원대**, 예외 처리와 다중 시스템 연동이 붙는
  프로세스 자동화는 **200만원대**까지 형성돼 있습니다
- **챗봇은 구간이 다릅니다.** 룰 기반이 300만~1,000만원대입니다
- **리드타임** — 1~3주. 문의 → 요건 정리 → 견적 → 제작 → 납품
- **확장** — 객단가와 가동 시간. 공수를 파는 구조입니다
- **한계** — **가동을 멈추면 매출도 멈춥니다.** 그리고 시간이 상한입니다

### ③ 운영 대행 · 구독

구축에서 끝내지 않고 매월 운영합니다. 콘텐츠 발행, 데이터 수집,
리포트 생성, 문의 1차 응대 같은 업무입니다.

- **단가** — 월 과금. LLM API를 태우는 서비스는 **운영비만 월 30만~200만원**
  규모가 잡힙니다. 여기에 운영 마진이 붙습니다
- **리드타임** — 1개월 이상. 신뢰가 선행돼야 합니다
- **확장** — **누적됩니다.** 이번 달 계약이 다음 달에도 살아 있습니다
- **한계** — 판매 난이도가 가장 높습니다. 매월 고정비를 승인하는 의사결정이라
  결재선이 깁니다

### ④ 교육 · 컨설팅

- **단가** — 시간당 또는 회차당. 편차가 큽니다
- **리드타임** — 가장 깁니다. 레퍼런스가 선행돼야 합니다
- **확장** — 가동 시간, 또는 녹화해서 ①번으로 전환
- **한계** — **실적 없이는 시작 자체가 안 됩니다**

### 비교표

| | 객단가 | 리드타임 | 확장 방식 | 병목 |
|---|---|---|---|---|
| ① 제품 | 5천~5만원 | **며칠** | 수량 | 트래픽 |
| ② 제작 대행 | 15만~200만원 | 1~3주 | 가동 시간 | 내 공수 |
| ③ 운영 대행 | 월 과금 | 1개월+ | **누적** | 판매 난이도 |
| ④ 교육 | 편차 큼 | 가장 김 | 가동 시간 | 레퍼런스 |

> 단가는 2026년 7월 확인 기준이며 변동됩니다. 확인 경로는 부록 C에 있습니다.

## 2. 어떤 모델로 시작할 것인가

여기서 대부분 판단을 틀립니다. **가장 좋아 보이는 걸 고르기 때문입니다.**

①번이 제일 매력적으로 보입니다. 자동으로 매출이 발생하니까요.
그런데 ①번은 **트래픽이 없으면 0원입니다.** 팔로워도 검색 유입도 없는 상태에서
전자책을 등록하면 아무 일도 일어나지 않습니다.

### 판단 기준은 두 개

**하나. 자금 여유가 얼마나 있는가.**
**둘. 접근 가능한 오디언스가 있는가** — 팔로워, 기존 고객, 업계 네트워크 중 아무거나.

| | 오디언스 있음 | 오디언스 없음 |
|---|---|---|
| **자금 급함** | ① 제품 — 바로 전환된다 | **② 제작 대행** — 건당 단가가 크다 |
| **여유 있음** | ③ 운영 대행 — 리커링을 쌓는다 | ② 로 시작해 ①③ 으로 확장 |

**오디언스가 없고 자금이 급하면 ②번입니다.** 건당 30만~100만원이니 몇 건이면
목표에 닿습니다. 반대로 ①번으로 같은 금액을 만들려면 수십 건이 필요하고,
트래픽이 없으면 수십 명이 모이지 않습니다.

> **소수에게 고단가로 파는 쪽이 먼저입니다.**
> 다수에게 저단가로 파는 모델은 트래픽이 생긴 다음에 엽니다.

### 대부분 순서를 반대로 갑니다

전자책이 제작 난이도가 낮아 보이니 그것부터 만듭니다. 만들고 나서
트래픽이 없다는 걸 확인합니다. 순서가 뒤집힌 겁니다.

**②번으로 첫 매출을 만들고, 거기서 생긴 레퍼런스와 고객으로 ①③번을 여는 것이
실제 순서입니다.** ②번은 매출 외에도 세 가지를 남깁니다.

- **레퍼런스** — ①③번의 전환율을 결정하는 자산
- **실제 페인포인트 데이터** — ①번에서 무엇을 팔지가 여기서 나옵니다
- **가격 감각** — 시장이 얼마를 지불하는지 몸으로 알게 됩니다

### 다만 ②번에 머무르면 안 됩니다

가동 시간이 상한입니다. **같은 요청이 세 번 들어오면 그건 제품화(①) 또는
구독화(③) 신호입니다.** 매번 새로 만들면 단가는 그대로인데 공수만 늡니다.

## 3. 무엇을 팔 것인가

모델을 정했으면 아이템입니다.

### 내가 가진 것에서 출발하지 않습니다

가장 흔한 실수입니다. 만든 게 있으면 그걸 팔고 싶어집니다.
그런데 시장은 **내 보유 자산에 관심이 없습니다. 자기 페인포인트에만 관심이 있습니다.**

이 차이가 결과를 가릅니다. 같은 공수를 들여도, 보유 자산에서 출발한 상품은
"그래서 이게 나한테 왜 필요한데"에서 막히고, 페인포인트에서 출발한 상품은
설명이 필요 없습니다.

### 페인포인트를 찾는 질문

여러 개 물을 필요 없습니다. 하나면 됩니다.

> **최근에 뭔가 해결하려고 검색했는데 답이 안 나왔던 게 있는가.**

답이 없다는 건 시장에 자료가 없다는 뜻이고, 그게 공백입니다.
그리고 내가 검색했다는 건 **최소 한 명에게는 수요가 실재했다**는 증거입니다.

### 모델별 아이템 발굴법

**② 제작 대행** — **타인이 반복하는 업무**를 찾습니다.
엑셀 정리, 자료 수집, 보고서 작성, 재고·주문 대조, 문의 1차 응대.
**기술 난이도가 핵심이 아닙니다.** 15만원짜리 엑셀 자동화가 꾸준히 팔리는 건
그 업무가 지겨운 사람이 많기 때문입니다. 화려한 기술은 오히려 견적을 부풀립니다.

**① 제품** — **내가 반복해서 설명한 것**을 찾습니다.
같은 내용을 세 번 이상 설명했다면 그건 이미 검증된 상품입니다.

**③ 운영 대행** — **②번 고객에게 "매월 운영해 드릴까요"를 제안**하는 것이
가장 빠릅니다. 신규 고객 획득보다 기존 고객 확장이 훨씬 쌉니다.

### 시장 검증 — 지어낸 조사에 속지 않기

AI에게 "이 시장 규모가 얼마냐"고 물으면 **그럴듯한 숫자를 생성합니다.**
검색 능력이 없는데 물으니 만들어내는 겁니다. 그 숫자를 근거로 아이템을 정하면
검증 없이 출발하는 것과 같습니다.

대신 이렇게 합니다.

1. 아이템 키워드를 **크몽·숨고에 그대로 검색**합니다
2. 등록된 서비스 **수, 가격대, 리뷰 수**를 봅니다
3. **리뷰가 달린 서비스가 있으면 그 시장은 실재합니다**
4. 등록은 많은데 리뷰가 전부 0이면 **공급만 있고 수요가 없는 카테고리**입니다

**리뷰 수가 가장 정직한 지표입니다.** 등록 수는 진입 장벽이 낮다는 뜻이지
수요가 있다는 뜻이 아닙니다.

## 4. 견적을 어떻게 산정하는가

②③번으로 간다면 여기가 실질적인 첫 관문입니다.
문의는 왔는데 얼마를 불러야 할지 몰라서 놓치는 경우가 가장 많습니다.

### 시간으로 계산하고, 시장가로 검증합니다

**1단계 — 공수를 시간으로 추정합니다.**
요건 정리, 제작, 테스트, 납품 설명, 수정 1회까지 포함합니다.
**테스트와 수정을 빼고 추정하면 반드시 적자가 납니다.**

**2단계 — 목표 시급을 곱합니다.**
초기에는 3만~5만원으로 잡습니다. 8시간짜리 작업이면 24만~40만원입니다.

**3단계 — 시장가와 비교합니다.**
업무 자동화 평균이 20만원, 주력 구간이 30만~100만원입니다.
계산값이 이 범위를 크게 벗어나면 둘 중 하나입니다 — 범위를 과하게 잡았거나,
반대로 공수를 과소평가했거나.

**4단계 — 추정 공수에 1.5를 곱합니다.**
처음에는 예외 처리에서 반드시 시간이 샙니다. 이건 낙관 편향이라
경험으로도 잘 안 고쳐집니다. 계수로 처리하는 게 안전합니다.

### 견적보다 범위를 먼저 자릅니다

**단가를 무너뜨리는 건 낮은 견적이 아니라 범위입니다.**

"자동화해 주세요"는 견적을 낼 수 없는 요청입니다. 이걸 그대로 받으면
납품 직전까지 요구사항이 계속 늘어납니다. 그래서 견적서를 보내기 전에
**범위를 문장으로 확정**합니다.

견적서에 반드시 들어가야 하는 항목입니다.

| 항목 | 왜 |
|---|---|
| **포함 범위** — 무엇을 만드는가 | 기준선 |
| **불포함 범위** — 무엇을 안 만드는가 | **이 줄이 없으면 범위가 무한대가 된다** |
| 산출물 형태 | 스크립트인지, 실행 파일인지, 설치까지인지 |
| 전제 조건 | 클라이언트가 제공할 계정·데이터·권한 |
| 수정 횟수 | 예: 납품 후 2회까지 무상 |
| 일정 | 착수일 기준 며칠 |
| 대금 조건 | 선금·잔금 비율과 시점 |
| 유지보수 | 별도 계약임을 명시 |

**불포함 범위가 가장 중요합니다.** "이건 이번 범위가 아닙니다. 필요하시면
별도로 견적 드리겠습니다"라고 쓸 수 있느냐가 수익성을 결정합니다.

### 대금 조건 — 선금을 받습니다

디지털 작업물은 납품 즉시 복제가 가능합니다. 그래서 **전액 후불은 위험합니다.**
실무에서 흔히 쓰는 구조는 이렇습니다.

- **선금 50% / 납품 시 잔금 50%**
- 규모가 크면 착수 30 / 중간 산출물 30 / 납품 40 으로 나눕니다
- 마켓플레이스를 경유하면 플랫폼이 에스크로 역할을 하므로 이 부담이 줄어듭니다.
  **초기 몇 건은 수수료를 내더라도 플랫폼을 쓰는 게 안전합니다**

### 첫 건은 낮게, 이유를 밝히고

레퍼런스가 0일 때는 시장가보다 낮게 시작하는 게 맞습니다.
다만 **왜 낮은지 반드시 밝히십시오.**

> "첫 레퍼런스를 만드는 단계라 이 가격입니다.
> 대신 완료 후 사례로 사용해도 될지 여쭙겠습니다."

이유 없이 싸면 품질이 낮다는 신호로 읽힙니다.
이유가 있으면 같은 가격이 **호의**로 읽힙니다.

## 5. 첫 문의부터 입금까지

문의가 왔을 때의 순서입니다. 여기서 헤매면 성사율이 떨어집니다.

### 순서

**① 요건을 질문으로 좁힙니다. 바로 견적을 내지 않습니다.**

첫 답장에서 가장 하면 안 되는 것이 즉답 견적입니다. 정보가 없는 상태의 견적은
반드시 틀리고, 한번 말한 금액은 올리기 어렵습니다.

물어야 할 것은 다섯 개입니다.

1. 지금은 그 업무를 **어떻게** 처리하고 계신가요
2. 한 번 처리하는 데 **얼마나** 걸리나요, **얼마나 자주** 하시나요
3. 데이터는 **어디에** 있나요 (엑셀, 웹, 사내 시스템)
4. 결과물은 **어떤 형태로** 받아야 하나요
5. **언제까지** 필요하신가요

**2번이 핵심입니다.** 여기서 나온 시간이 곧 클라이언트가 느끼는 가치이고,
견적의 근거가 됩니다. "주 5시간 걸리신다니 월 20시간입니다"라고 환산해서
되돌려주면 금액 저항이 크게 줄어듭니다.

**② 범위를 문장으로 확정하고 확인받습니다.**

> "정리하면 이렇습니다. A를 자동으로 수집해서 B 형태로 정리하고 C로 내보내는
> 것까지입니다. D는 이번 범위에 포함하지 않습니다. 맞을까요?"

**이 확인 한 번이 분쟁의 대부분을 막습니다.**

**③ 견적서를 보냅니다.** 앞 장의 8개 항목을 채웁니다.

**④ 선금 입금 후 착수합니다.** 입금 전 착수는 하지 않습니다.
"먼저 좀 보여주시면"에 응하면 거의 무상 작업으로 끝납니다.

**⑤ 중간 공유를 한 번 합니다.** 완성본을 한 번에 보여주면 방향이 어긋났을 때
전부 다시 해야 합니다. 절반 시점에 한 번 보여주는 것이 가장 저렴한 보험입니다.

**⑥ 납품 시 사용법을 문서로 같이 줍니다.**
이게 없으면 문의가 무한정 들어옵니다. A4 한 장이면 충분합니다.

**⑦ 잔금 청구, 그리고 레퍼런스를 요청합니다.**

### 범위가 늘어날 때의 대응

작업 중 "이것도 같이 되나요"는 반드시 나옵니다. 거절이 아니라 **분리**로 답합니다.

> "가능합니다. 다만 이번 범위에는 없던 항목이라 별도로 견적 드리겠습니다.
> 지금 진행 중인 건은 예정대로 마무리하겠습니다."

**무상으로 얹어주는 것이 호의로 돌아오지 않습니다.** 다음 요청의 기준선이 됩니다.

### 유지보수는 분리합니다

납품 후 "조금만 고쳐주세요"가 계속되면 시급이 0에 수렴합니다.
견적서에 미리 적어둡니다.

- 납품 후 **N일 이내, M회까지** 무상 수정 (설명과 다르게 동작하는 경우)
- 기능 추가·환경 변경은 별도 건
- 월 단위 운영이 필요하면 **③번 모델로 전환** 제안

**이 마지막 줄이 ③번 모델의 진입점입니다.** 신규 영업보다 훨씬 쉽습니다.

## 6. 리드는 어디서 오는가

### 객단가가 접근 방식을 결정합니다

| 객단가 | 접근 |
|---|---|
| 30만원 이상 | **1:1 제안이 유효하다.** 상대에게 비용 대비 효익이 계산된다 |
| 3만원 안팎 | **1:1 제안이 무효하다.** 콘텐츠로 유입시켜야 한다 |

3만원짜리를 콜드 메시지로 파는 건 계산이 맞지 않습니다. 전환율 1%로 30건을
만들려면 3,000통이 필요하고, 그 볼륨은 스팸이며 계정 정지 사유입니다.
받는 쪽 입장에서도 3만원 광고를 읽을 유인이 없습니다.

반대로 **②번은 콜드로 접근하기 좋습니다.** "주 5시간 쓰시는 업무를 자동화하면
어떻게 되는지"는 상대가 계산할 수 있는 제안이기 때문입니다.

### 고단가 — 1:1 제안

**대상 선정이 문안보다 중요합니다.** 반복 업무가 눈에 보이는 곳을 고릅니다.
주문·재고를 수기로 관리하는 소매업, 정산을 엑셀로 하는 소규모 업체,
문의 응대에 시간을 쓰는 서비스업.

제안은 300자 이내로 씁니다. 구조는 넷입니다.

1. 상대가 반복하고 있을 업무 (추측이면 추측이라고 밝힙니다)
2. 자동화하면 어떻게 바뀌는지
3. 무엇을 만들 것인지 구체적으로
4. 금액과 기간

**절감액을 숫자로 단정하지 않습니다.** 확인되지 않은 수치는 신뢰를 깎고,
과장 광고 소지도 있습니다.

### 저단가 — 콘텐츠로 유입

판매 목적의 글은 확산되지 않고, **도움이 되는 글은 확산됩니다.**
알고리즘이 댓글과 체류시간을 보기 때문이기도 하고, 사람이 광고를 안 읽기
때문이기도 합니다.

실행은 단순합니다.

- 사람들이 **이미 공개적으로 질문한 곳**을 찾습니다
- **링크 없이 답변만 합니다.** 대부분의 커뮤니티가 홍보를 금지하고,
  링크가 붙는 순간 답변이 광고로 읽힙니다
- 링크는 프로필에 둡니다. 답변이 좋으면 프로필로 들어옵니다
- **답변 글이 판매 글보다 최소 3배 많아야 합니다**

### 판매 과정을 콘텐츠로 씁니다

상품 소개는 한 번 하면 더 쓸 말이 없습니다. 그런데 **판매 진행 상황을 공개하면
소재가 계속 생깁니다.**

오픈했습니다 → 아직 0건입니다 → 첫 건이 나왔습니다 → 3건째입니다 →
절반입니다 → 마감했습니다.

**안 팔리는 상황도 소재가 됩니다.** "아직 0건"은 실패 보고가 아니라
다음 화 예고입니다. 이 방식을 쓰는 사람이 드물어서 눈에 띕니다.

## 7. 가격 정책

### 제품(①)은 정찰제로 두면 아무 일도 안 일어납니다

오늘도 3만원, 내일도 3만원이면 오늘 살 이유가 없습니다.
그리고 내일이 되면 잊습니다.

### 한정 수량 + 건당 인상

- 수량을 한정합니다
- **1건 판매될 때마다 가격을 소폭 인상합니다**
- 완판 시 판매를 종료합니다

효과가 세 겹입니다.

**하나. 지금 구매할 이유가 생깁니다.** 내일은 더 비쌉니다.
**둘. 콘텐츠 소재가 생깁니다.** "3건 나갔고 가격이 올랐습니다"가 그 자체로 글입니다.
**셋. 초기 구매자가 보상받습니다.** 먼저 산 쪽이 가장 저렴하므로
레퍼런스 요청이 자연스러워집니다.

### 지켜야 할 것

**규칙을 공표하고 지킵니다.** 30개 한정이라고 했으면 30개에서 닫습니다.
반응이 좋다고 늘리면 **다음 판매에서 신뢰를 잃습니다.**

**현재 가격을 상시 노출합니다.** 인상이 보이지 않으면 정찰제와 같습니다.

**과도하게 낮게 걸지 않습니다.** 저가는 오히려 저항을 만듭니다.
시간을 쓸 가치가 없다는 신호로 읽힙니다.

### 대행(②)의 가격 전략은 다릅니다

한정·인상 장치는 제품에만 유효합니다. 대행은 **레퍼런스가 쌓일 때마다
다음 견적을 올리는** 방식으로 갑니다.

- 1~2건차: 시장가 하단, 이유를 밝히고
- 3~5건차: 시장가
- 그 이후: 시장가 상단, 또는 특정 업종 특화로 포지셔닝

**같은 작업을 반복하면 공수가 줄어드는데 단가는 유지되므로 시급이 올라갑니다.**
그게 대행의 유일한 확장 경로입니다.

## 8. 레퍼런스가 0일 때

첫 판매에서 전부 여기서 막힙니다. 리뷰가 없으니 안 팔리고, 안 팔리니
리뷰가 안 쌓입니다.

허위 리뷰는 논외입니다. **위법이고, 적발되며, 적발되면 회복이 안 됩니다.**

리뷰가 수행하는 기능은 하나입니다 — **"이 사람 말이 사실인가"를 대신 검증**하는 것.
그 기능을 하는 다른 수단이 있으면 됩니다.

### 대체 수단 다섯

**하나. 미리보기.** 앞부분을 공개합니다. 직접 보고 판단하게 하는 것이
타인의 리뷰보다 강합니다. 환불 분쟁도 같이 줄어듭니다.

**둘. 실시간 시연.** 상대가 제공한 데이터로 즉석에서 돌려 보입니다.
**위조가 불가능합니다.** 리뷰는 조작할 수 있지만 눈앞의 실행은 못 꾸밉니다.
②번에서는 이것이 리뷰보다 강력한 클로징 도구입니다.

**셋. 무상 파일럿.** 범위를 아주 작게 잘라 무상으로 한 건 해줍니다.
**전체를 무상으로 하는 게 아닙니다** — 2시간짜리 한 조각만입니다.
결과가 나오면 그게 곧 레퍼런스이자 견적의 근거가 됩니다.

**넷. 검증 가능한 사실.** 상대가 직접 확인할 수 있는 정보를 제시합니다.
하나가 맞으면 나머지도 신뢰됩니다.

**다섯. 인접 경력.** AI 관련 실적이 없어도 판매·운영 경험이 있다면 근거입니다.
사업자등록, 운영 중인 채널처럼 **열어보면 확인되는 것**이 가장 강합니다.
다만 **없는 것과 있는 것을 섞지 않습니다.** 경계를 흐리면 과장이 되고,
하나가 걸리면 나머지 주장도 함께 의심받습니다.

### 초기 고객은 레퍼런스 자산입니다

매출로만 보지 않습니다.

- 낮은 가격에 **이유를 붙여** 제공합니다
- 완료 후 **무엇이 부족했는지** 물어봅니다. 그 답이 다음 버전입니다
- 리뷰를 요청하되 **내용을 지정하지 않습니다.** 지정하는 순간 광고가 됩니다
- **사례 사용 동의를 명시적으로 받습니다.** 구두 승낙 말고 텍스트로 남깁니다

## 9. 결제 채널과 수수료

여기부터는 실행 단계입니다.

**① PG (토스페이먼츠 등)** — 결제 처리만 합니다. 상품 페이지도 파일 전달도
제공하지 않습니다. **PG 연동이 곧 자동 발송이 아닙니다.**

**② 마켓플레이스 (크몽 등)** — 트래픽이 이미 있습니다. 대신 심사가 있고
수수료가 높으며, 고객이 플랫폼 고객입니다.

**③ 오픈마켓 (스마트스토어 등)** — 검색 유입이 강합니다.
그런데 **파일 자동 발송 기능이 없습니다.**

**④ 디지털 상품 스토어프론트** — 상품 페이지·결제·자동 발송이 한 덩어리입니다.

### 실제 수수료 — 2026년 7월 확인 기준

| 플랫폼 | 수수료 | 정산 | 자동 발송 | 사업자등록 |
|---|---|---|---|---|
| 래피드 | **1.6%** | — | 결제 즉시 | 불필요 |
| 리틀리 | **1~5%** (판매량 연동) | 주 1회 자동 | 결제 즉시 | 연 20건까지 불필요 |
| 크몽 | **4.4~16.4%** (금액 구간별) | 월 말 영업일 | 있음 | 필요 (심사) |
| 스마트스토어 | 결제 **1.98~3.63%** (VAT 포함)<br>+ 판매 **2.73%** (VAT 별도) | 구매확정 후 D+3~D+7 | **없음** | 필요 |

> 확인 시점 기준이며 변동됩니다. 스마트스토어는 2025년에만 두 차례 조정됐습니다.
> 본인 등급별 실제 요율은 각 플랫폼 정산 화면에서 확인하십시오.

### 판단 포인트 넷

**하나. 마켓플레이스와 스토어프론트가 열 배 이상 차이 납니다.**
탈잉 20% 대 래피드 1.6%. 29,000원 상품이면 5,800원 대 464원입니다.
**그 차이가 트래픽의 가격입니다.**

**둘. 크몽은 금액 구간별이라 소액에 불리합니다.**
다만 **②번처럼 객단가가 높으면 계산이 달라집니다** — 트래픽이 있는 곳에서
50만원을 파는 편이, 트래픽이 없는 곳에서 수수료를 아끼는 것보다 낫습니다.
**초기에는 수수료보다 첫 건이 중요합니다.**

**셋. 스마트스토어는 수수료보다 정산 주기가 변수입니다.**
합산 6% 안팎이라 요율은 나쁘지 않은데 **정산이 구매확정 이후**라
주문부터 입금까지 실질 2~3주 걸립니다.

**넷. PG 수수료는 등급에 따라 다섯 배 차이 납니다.**
일반 3.4%, 영세 0.63%. 매출 규모로 자동 산정되므로 별도 신청이 필요 없습니다.

## 10. 납품과 전달

**결제와 전달은 별개 문제입니다.** 결제 수단을 붙였다고 전달이 해결되지 않습니다.

### 경로별 — 2026년 7월 확인 기준

| 경로 | 전달 방식 | 직접 구현할 것 |
|---|---|---|
| 래피드 | 결제 완료 시 자동 발송 | 없음 |
| 리틀리 | 결제 완료 시 메일·카카오톡 자동 발송 | 없음 |
| 크몽 | 플랫폼이 처리 | 없음 |
| 스마트스토어 | **기본 기능 없음.** 발주/발송관리에서 수동 처리 | 외부 도구 또는 수작업 |
| PG 직결 | 결제 성공 신호만 수신 | 웹훅 서버 + 발송 로직 |

스마트스토어는 완전히 막힌 건 아닙니다. **센드맨 같은 외부 도구를 연동하면**
주문 즉시 파일이나 1회용 다운로드 코드를 발송할 수 있습니다.
질문을 "자동 발송이 되는가"가 아니라 **"무엇을 붙이면 자동이 되는가"**로
바꿔야 합니다.

### 채널 선택 전 확인할 세 가지

**하나. 결제 완료 시 자동 발송이 되는가.**

**둘. 파일 교체 시 기존 구매자도 최신본을 받는가.**
링크가 고정되는 방식이면 파일만 교체하면 됩니다. 아니면 개정할 때마다
전체 구매자에게 재발송해야 합니다. 20명은 되지만 200명은 불가능합니다.

**셋. 다운로드 제한이 있는가.**
횟수 제한이나 기간 만료가 있으면 "평생 소장"으로 표기할 수 없습니다.
표기하면 허위 표시입니다.

### 수동 발송이라면

- **발송 소요 시간을 페이지에 명시합니다.** 없으면 "언제 오나요" 문의가
  판매량만큼 발생합니다. 12시간 정도가 무난합니다
- 파일은 클라우드에 두되 **업데이트 시 링크를 바꾸지 않습니다.**
  신규 업로드가 아니라 같은 파일의 새 버전으로 교체합니다
- **유출은 통제 불가능합니다.** 이 규모에서 DRM은 비용 대비 효과가 없습니다.
  유출을 전제로 가격을 정하고, 지속적인 업데이트로 최신본의 출처를
  독점하는 편이 현실적입니다

### 자동 발송이라면

- 파일이 실제로 첨부됐는지 확인합니다
- **본인이 직접 1건 결제해 봅니다.** 다른 결제수단으로 최저가 상품을 걸어
  구매하고, 메일 수신과 파일 열림을 확인합니다. 5분이면 됩니다

## 11. 법무와 세무

> 실무에서 통용되는 정리이며 법률 자문이 아닙니다.
> 규모가 커지거나 분쟁이 발생하면 세무사·변호사 확인이 필요합니다.

### ① 사업자등록과 통신판매업

**사업자등록**은 계속·반복 판매하면 필요합니다. 홈택스에서 온라인 처리됩니다.

**통신판매업 신고**는 별개 절차입니다. 관할 구청·시청에 합니다.
**다만 면제 기준이 있습니다.**

공정거래위원회 고시상 다음 **둘 중 하나**면 신고 의무가 면제됩니다.

> **직전 연도 통신판매 거래 횟수 50회 미만**
> **또는**
> **부가가치세법상 간이과세자**

"또는"입니다. 간이과세자 기준은 **연 매출 1억 400만원 미만**입니다.

| 상황 | 신고 |
|---|---|
| 시작 단계, 전년도 거래 0건 | 면제 |
| 간이과세자 | 면제 (기준 유지되는 동안) |
| 전년도 50회 이상 + 일반과세자 | 필요 |

시작 단계라면 대부분 면제입니다. 다만 **면제라도 판매 페이지에 사업자 정보는
표시해야 합니다.**

신고번호를 조회하면 "번호: 1" 같은 값이 표시되는데 **그건 검색 결과 순번이지
신고번호가 아닙니다.** 실제 번호는 제0000-지역명-0000호 형식입니다.

### ② 판매 페이지 필수 표기

상호 · 대표자명 · 사업장 주소 · 전화번호 · 이메일 · 사업자등록번호 ·
통신판매업 신고번호.

**전화번호가 의무입니다.** 개인 휴대폰을 공개하면 스팸과 영업 전화가
유입됩니다. **통신사 투넘버 부가서비스**가 가장 빠릅니다 — 앱에서 즉시 개통되고
월 3천원대입니다.

### ③ 환불 규정

가장 흔한 실수가 이것입니다.

> "환불은 결제하신 채널의 정책을 따릅니다."

**분쟁 시 규정을 고지하지 않은 쪽이 불리합니다.**

디지털 상품은 조건을 갖추면 청약철회를 제한할 수 있습니다.
근거는 전자상거래법 제17조 제2항 제5호이고, **핵심 조건이 사전 고지**입니다.
구매 시점에 몰랐다고 하면 제한이 적용되지 않습니다.

```
[전달 전]
파일이나 다운로드 링크를 보내드리기 전이면 전액 환불됩니다.

[전달 후]
파일을 받으신 뒤에는 청약철회가 제한됩니다. 디지털 파일은 전달 즉시
복제가 가능하기 때문이며, 이 안내가 전자상거래법 제17조 제2항 제5호가
요구하는 사전 고지입니다.

[하자]
파일이 열리지 않거나 상세페이지 설명과 다른 경우는 하자이므로
환불 대상입니다.

[미리보기]
구매 전에 앞부분을 확인하실 수 있습니다.
```

**미리보기 항목이 실질적으로 가장 강한 방어입니다.** 사전에 확인 가능하면
"설명과 다르다"는 분쟁 자체가 거의 발생하지 않습니다.

**용역(②③)은 구조가 다릅니다.** 착수 후에는 기 진행분에 대한 대가가
발생하므로, 견적서에 **중도 해지 시 정산 기준**을 미리 적어둡니다.

### ④ 표시광고법

**수익 금액을 약속하지 않습니다.**

"월 300 가능", "3일이면 본전", "따라만 하면 수익화" — 거짓·과장 광고가 될 수
있고, 분쟁 시 전액 환불에 행정 처분까지 이어집니다.

실무적으로도 **이런 문구를 쓴 상품이 환불 요구가 가장 많습니다.**
기대치를 판매자가 올려놓았기 때문입니다.

대신 판매 가능한 것은 **소요 시간의 단축과 실행 순서**입니다.
검증 가능하고 약속을 어길 일이 없습니다.

### ⑤ 부가세와 세금계산서

- **판매가에 부가세를 포함할지 별도로 할지** 사전에 정합니다.
  나중에 변경하면 기존 구매자와 형평이 맞지 않습니다
- **법인·대행사 대상이면 세금계산서 발행 여부가 결정적입니다.**
  발행이 안 되면 상대는 구매 품의를 올릴 수 없습니다.
  가능하면 개인 대상보다 객단가를 크게 올릴 수 있고,
  ②③번 모델에서 특히 차이가 큽니다

## 12. 반복 가능한 구조로 만들기

첫 매출 이후가 실질적인 시작입니다.

**같은 요청이 세 번 들어오면 제품화합니다.** ②번에서 반복되는 작업은
①③번의 원형입니다. 매번 새로 만들면 공수만 늡니다.

**②번 고객에게 ③번을 제안합니다.** "매월 운영해 드릴까요"는 신규 영업보다
훨씬 성사율이 높습니다.

**모든 건에서 레퍼런스와 사례를 확보합니다.** 그것이 다음 견적의 근거입니다.

**업종을 좁힙니다.** "업무 자동화 해드립니다"보다 "쇼핑몰 주문·정산 자동화"가
전환율이 높고 단가도 높습니다. 좁힐수록 견적 근거가 명확해지기 때문입니다.

그리고 **초기 반응이 없다고 조기에 접지 않습니다.**
대부분 초반에는 반응이 없고, 방향을 한 번 조정한 뒤에 움직입니다.

## 부록 A. 복붙 프롬프트 {: .page-break }

대괄호 안만 본인 상황으로 바꿔서 쓰시면 됩니다.

> **공통 주의.** 모델은 모른다고 답하는 대신 **그럴듯하게 생성합니다.**
> 시장 규모, 경쟁사 목록, 법 조항 번호처럼 검증이 필요한 값을 요구하면
> 확신에 찬 오답이 돌아옵니다. 아래 프롬프트는 **모델이 생성할 수 없는 값을
> 애초에 요구하지 않도록** 설계돼 있습니다.

### A-1. 수익 모델 선택

```
내 조건이다.
- AI로 가능한 작업: [구체적으로]
- 주당 가용 시간: [ ]
- 접근 가능한 오디언스: [팔로워/기존 고객/업계 네트워크, 없으면 없다고]
- 자금 여유: [당장 필요 / 3개월 / 여유 있음]

아래 네 모델의 우선순위를 매기고 근거를 적어라.
① 제품 판매 (객단가 낮음, 리드타임 며칠, 트래픽 없으면 0)
② 제작 대행 (객단가 15만~200만원, 리드타임 1~3주, 내 공수가 상한)
③ 운영 대행·구독 (월 과금, 리드타임 1개월+, 누적, 판매 난이도 높음)
④ 교육·컨설팅 (레퍼런스 선행 필요)

각 순위마다 적을 것
- 내 조건의 어떤 항목 때문에 이 순위인가
- 첫 매출까지 실행할 작업 3가지
- 이 모델에서 내가 이탈할 가능성이 가장 큰 지점

금지
- 수익 금액이나 달성 확률을 예측하지 마라
- 시장 규모 같은 숫자를 생성하지 마라
- 내가 제시하지 않은 조건을 가정하지 마라
```

### A-2. 아이템 발굴

```
나는 [가능한 작업 / 겪은 문제]를 보유하고 있고,
[① 제품 / ② 제작 대행 / ③ 운영 대행] 모델로 진행하려 한다.

아이템 후보를 5개 도출해라.

각 후보마다
1. 타겟 (구체적 상황으로. "직장인" 말고
   "주문·재고를 엑셀로 수기 관리하는 1인 쇼핑몰 운영자")
2. 그 타겟의 페인포인트 한 문장
3. 내가 직접 검증할 수 있는 검색어 3개
   (크몽·숨고에 그대로 입력 가능한 형태)
4. 지금 그 타겟은 이 문제를 어떻게 처리하고 있을 것 같은가

마지막에 5개를 시장 크기 순으로 배열하고 가장 좁은 것과 넓은 것을 표시해라.

금지
- 보유 자산이 아니라 타겟의 페인포인트에서 출발해라
- **수치를 추정하지 마라.** 시장 규모, 검색량, 경쟁 서비스 수는
  네가 확인할 수 없다. 모르면 모른다고 해라
- **실재하는 서비스명·상품명을 예시로 들지 마라**
- 수익 금액을 약속하는 표현 금지
```

### A-3. 요건 정리 (문의 응대용)

```
클라이언트 문의 내용이다.
[문의 원문 붙여넣기]

바로 견적을 내지 말고, 견적에 필요한 정보를 얻기 위한 질문을 5개 이내로 만들어라.

반드시 포함할 것
- 현재 그 업무를 어떻게 처리하는지
- 1회 소요 시간과 빈도
- 데이터 위치와 형식
- 결과물 형태
- 희망 일정

그리고 문의 내용에서 **범위가 불명확한 부분**을 따로 지적해라.
견적 전에 확정해야 할 항목이 무엇인지 목록으로 달라.

규칙
- 질문은 답하기 쉽게. 한 문장에 하나씩
- 전문 용어를 쓰지 마라. 상대는 비개발자일 가능성이 높다
- 금액을 먼저 언급하지 마라
```

### A-4. 견적서

```
작업 내용: [무엇을 만들 것인가]
추정 공수: [시간]
목표 시급: [금액]
클라이언트가 제공할 것: [계정, 데이터, 권한 등]

견적서를 작성해라. 아래 항목을 모두 포함한다.

1. 포함 범위 — 무엇을 만드는가 (구체적으로)
2. **불포함 범위 — 무엇을 만들지 않는가**
3. 산출물 형태
4. 전제 조건 (클라이언트 제공 항목)
5. 수정 횟수와 조건
6. 일정 (착수일 기준)
7. 대금 조건 (선금·잔금 비율과 시점)
8. 유지보수 — 별도 계약임을 명시
9. 중도 해지 시 정산 기준

규칙
- 2번을 반드시 구체적으로 써라. 이 항목이 없으면 범위가 무한대가 된다
- 성과나 절감액을 숫자로 약속하지 마라
- 전문 용어에는 괄호로 짧은 설명을 붙여라
```

### A-5. 상세페이지 / 서비스 소개

```
아래를 판매하는 페이지 문안을 작성해라.
[상품 또는 서비스 설명 붙여넣기]

구조
1. 후킹 — 타겟이 현재 겪고 있는 상황 한 문장. 상품 언급 금지
2. 문제 — 그 상황이 지속되는 이유
3. 제공 범위
4. **제공하지 않는 범위** — 반드시 포함. 신뢰가 여기서 나온다
5. 미리보기 또는 시연 안내
6. 가격 (제품이면 수량 정책 포함)
7. 환불 규정
8. 판매자 정보

금지
- 수익 보장 표현
- 없는 리뷰를 암시하는 표현
- 공포를 이용한 긴급성. 긴급성은 가격 정책으로만 만든다
```

### A-6. 환불 규정

```
디지털 상품 판매용 환불 규정을 작성해라.

근거 조항은 아래를 그대로 사용한다. 다른 조항 번호를 생성하지 마라.
  전자상거래 등에서의 소비자보호에 관한 법률 제17조 제2항 제5호

포함할 것
- 전달 전: 전액 환불
- 전달 후: 청약철회 제한. 위 조항 인용, 이 안내가 사전 고지임을 명시
- 하자(열림 불가, 설명 불일치): 환불
- 구매 전 미리보기 안내
- 외부 채널 결제 시 해당 채널 절차가 함께 적용된다는 안내

금지
- "채널 정책을 따릅니다"로 종결하는 것
- **위에 제시한 것 외의 조항 번호나 법령명을 쓰는 것**
- 플랫폼 약관 원문을 그대로 옮기는 것.
  판매자 적용 조항과 구매자 적용 조항을 구분해라
```

### A-7. 판매 진행 공개

```
현재 상황: [예: 3건째 판매 완료. 현재 가격 32,000원. 목표 30건]

이 상황을 SNS 게시물로 작성해라.

규칙
- 상품 소개가 아니라 진행 상황 공개다. 지금 발생한 일 하나만 다뤄라
- 500자 이내
```

- [ ] 선금 비율과 시점을 명시했는가

- [ ] 유지보수가 별도 계약임을 적었는가

- [ ] 중간 공유 시점을 잡았는가

- [ ] 전화번호가 공개해도 되는 번호인가
- [ ] 환불 규정에 전달 전/후/하자가 모두 있는가

## 부록 C. 수치 확인 경로 {: .page-break }

본문 수치는 **2026년 7월 확인 기준**이며 변동됩니다.
숫자보다 **확인 경로**가 오래 갑니다.

| 항목 | 확인처 |
|---|---|
| 제작 대행 시장 단가 | 크몽·숨고에서 동일 품목 검색. **리뷰 수를 함께 볼 것** |
| 스마트스토어 본인 요율 | 정산관리 → 나의 수수료 정보 |
| PG 카드 수수료 등급 | PG사 관리자 → 가맹점 정보 (매출 규모로 자동 산정) |
| 크몽 구간별 수수료 | 크몽 판매자 가이드. 본인 가격대를 대입할 것 |
| 스토어프론트 요율 | 각 서비스 요금 안내 |
| 통신판매업 면제 여부 | 관할 시청·구청 지역경제과 |
| 본인 통신판매업 신고번호 | 기존 판매 페이지 하단 표기 |
| 간이과세 여부 | 홈택스 → 사업자 정보 |
| 플랫폼 환불 규정 | 각 플랫폼 이용약관 **원문** |

### 확인 시 주의 세 가지

**하나. VAT 포함/별도가 표기되지 않은 요율이 많습니다.**
3.63%(포함)와 2.73%(별도)를 나란히 비교하면 안 됩니다. 기준을 통일하십시오.

**둘. "수수료"에 여러 종류가 섞여 있습니다.**
스마트스토어는 결제수수료와 판매수수료가 별개입니다. **합산으로 비교하십시오.**

**셋. 정산 주기를 수수료와 함께 보십시오.**
요율 1%p 차이보다 정산 2주 지연이 더 큰 제약일 때가 많습니다.
초기에는 그 자금이 다음 작업의 원가입니다.

### 출처

플랫폼 요율·정산 주기와 제작 대행 시장 단가는 각 서비스의 공개 안내와
카테고리 페이지에서, 통신판매업 면제 기준은 공정거래위원회 고시에서
확인했습니다. 법 조항은 전자상거래 등에서의 소비자보호에 관한 법률
원문 기준입니다.

오류를 발견하시면 알려주십시오. 개정판에 반영되며 같은 링크에서
최신본이 열립니다.

## 마치며

결론은 한 문장입니다.

> **AI를 더 배운다고 매출이 생기지 않습니다.
> 수익 모델을 정하고 첫 고객을 만나야 생깁니다.**

그리고 순서가 있습니다. 오디언스가 없으면 **소수에게 고단가로** 파는 쪽이
먼저이고, 거기서 확보한 레퍼런스로 **다수에게 저단가로** 파는 모델을 엽니다.
대부분 이 순서를 반대로 실행해서 정체됩니다.

②번에서 첫 매출을 만들고, 반복되는 요청을 제품화하고, 기존 고객을 구독으로
전환하는 것 — 이것이 가장 짧은 경로입니다.

마지막으로, **완성도를 이유로 출시를 미루지 마십시오.**
가장 흔하고 가장 회복하기 어려운 실패입니다.
만드는 역량은 이미 갖추셨습니다. 남은 것은 판매 구조뿐입니다.
