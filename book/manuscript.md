# AI 활용할 줄은 아는데 어떻게 수익화 할까

등록부터 자동 유통까지 — 0에서 첫 매출까지의 전 과정

---

## 전체 지도

먼저 전체를 보고 시작합니다. **각 단계에서 무엇이 결정되는지** 알면
중간에 길을 잃지 않습니다.

```
1부  팔 수 있는 상태 만들기
     ① AI는 어디서 돈이 되는가  만들기·팔기·굴리기 / 사람과 AI의 분업
     ② 어디에 등록할 것인가     수수료·자동발송·트래픽 비교
     ③ 어떻게 등록하는가        상세페이지·미리보기·가격 정책
     ④ 결제와 전달             돈이 들어오고 물건이 나가는 경로
     ⑤ 법                      표기 의무·환불 규정·면제 기준

2부  유통 세우기
     ⑥ 유통 채널 지도          흐름형·축적형·직접형과 조합
     ⑦ 왜 자동화인가            반응 속도가 전환을 만든다
     ⑧ 계정 준비               3일 배치, 순서를 코드로 강제
     ⑨ 스레드에 붙이기          앱·토큰, 그리고 반드시 틀리는 세 곳

3부  봇 세 개
     ⑩ 발행 봇                 정해진 순서로 올린다
     ⑪ 응대 봇                 달린 댓글에 몇 분 안에 답한다
     ⑫ 중계 봇                 판매 상황을 사건으로 만든다

4부  전환과 유지
     ⑬ 전환 장치               링크 위치·글 비율·가격
     ⑭ 안전장치                계정을 죽이지 않기
     ⑮ 7일 실행                전체를 관통하는 순서

부록 A  프롬프트 — 한 방짜리가 아니라 이어지는 순서로
```

**1장을 건너뛰지 마세요.** AI를 이미 쓰고 계신다면 여기가 가장 중요합니다.
어디까지를 AI에게 맡기고 어디부터는 사람이 해야 하는지가 여기서 갈립니다.

### 이 자료의 대상

**ChatGPT나 클로드에 질문해 본 적이 있으면 됩니다.**
코딩은 몰라도 됩니다. 필요한 코드는 AI가 씁니다.
다만 터미널에 명령어를 붙여넣고 결과를 볼 줄은 알아야 합니다.

### 다루지 않는 것

- AI 도구 기초 사용법
- 브라우저 자동화 · 계정 다중 운영 같은 약관 위반 방식
- 유료 광고 집행
- 법률 · 세무 자문 (실무 정리까지)

수치는 확인해서 넣었고, 확인 경로를 부록 C에 함께 적었습니다.

# 1부 — 팔 수 있는 상태 만들기

## 1. AI는 어디서 돈이 되는가

### AI는 돈을 벌어주지 않습니다. 재고를 만들어줄 뿐입니다

이 문장부터 짚고 갑니다. **AI가 만들어내는 건 매출이 아니라 재고입니다.**
초안, 문서, 코드, 이미지. 팔 수 있는 물건이지 팔린 물건이 아닙니다.

AI를 쓰는데 돈이 안 되는 분들은 대개 실력이 부족해서가 아닙니다.
**재고만 쌓고 있어서 그렇습니다.** 결과물은 폴더에 계속 늘어나는데
결제창이 없으니 매출이 0입니다.

돈은 세 군데서 나옵니다.

| | 하는 일 | 없으면 |
|---|---|---|
| **① 만들기** | 팔 물건 자체를 만든다 | 팔 게 없다 |
| **② 팔기** | 상세페이지·문안·채널별 변환 | 있어도 안 팔린다 |
| **③ 굴리기** | 응대·중계를 24시간 돌린다 | 하루 반짝하고 끝난다 |

**셋 중 하나만 해서는 돈이 안 됩니다.** 그런데 대부분 ①만 합니다.
AI로 만드는 건 재미있고 즉시 결과가 보이는데, ②와 ③은 지루하고
결과가 늦게 나오기 때문입니다.

이 자료의 나머지 전부가 ②와 ③입니다. ①은 이미 하고 계실 테니까요.

### 어디까지 AI에게 맡기는가

가장 많이 받는 질문이고, 답이 명확합니다.

| 일 | 사람 | AI |
|---|---|---|
| 무엇을 팔지 정하기 | **결정** | 후보 넓히기 |
| 자료·콘텐츠 집필 | 검수 | **초안 전량** |
| 수치·요율·법 조항 | **확인** | **손대면 안 됨** |
| 가격·수량 정책 | **결정** | — |
| 상세페이지 문안 | 고르기 | **여러 안 생성** |
| 채널별로 다시 쓰기 | — | **전량** |
| 답글 응대 | 민감 건만 | **상시** |
| 판매 중계 | 수량 입력 | **전량** |

읽는 방법은 간단합니다. **틀렸을 때 되돌릴 수 없는 것만 사람이 합니다.**
잘못 나간 답글은 지우면 되지만, 상세페이지에 적힌 틀린 수수료율은
그걸 보고 산 사람에게 이미 피해를 준 뒤입니다.

> **모델은 모른다고 하지 않습니다. 그럴듯한 값을 만들어냅니다.**
> 수수료율, 정산 주기, 법 조항 번호를 물으면 확신에 찬 오답이 돌아옵니다.
> 이 자료의 프롬프트가 전부 "수치는 네가 쓰지 마라"로 시작하는 이유입니다.

### 실제로 얼마가 드는가

AI로 만든다고 공짜는 아닙니다. 시작 전에 알고 계시는 게 낫습니다.

| 항목 | 대략 |
|---|---|
| 집필용 구독 | 월 2~3만원 |
| 봇 운영 API | 답글 한 건에 수 원 수준. 하루 수십 건이면 월 몇천 원 |
| 사람 검수 | **여기가 제일 큽니다.** 초안이 빨리 나올수록 검수가 밀립니다 |

돈보다 시간이 병목입니다. **AI가 하루치 초안을 30분에 뽑아주면
검수도 30분 만에 끝날 것 같지만, 실제로는 검수가 더 걸립니다.**
그래서 3장 이후로 검수 항목을 체크리스트로 고정해뒀습니다.

### 무엇을 팔 것인가

**시장은 내가 무엇을 가졌는지에 관심이 없습니다. 자기 문제에만 관심이 있습니다.**
가진 것에서 출발한 상품은 "그래서 이게 나한테 왜 필요한데"에서 막히고,
페인포인트에서 출발한 상품은 설명이 필요 없습니다.

찾는 질문은 하나면 됩니다.

> **최근에 뭔가 해결하려고 검색했는데 답이 안 나왔던 게 있는가.**

답이 없다는 건 시장에 자료가 없다는 뜻이고, 내가 검색했다는 건
최소 한 명에게는 수요가 실재했다는 증거입니다.

### 카테고리별 페인포인트

각 항목이 그대로 자료 하나의 주제가 됩니다.

**① 1인 판매자 · 소상공인**
주문·재고 수기 대조 / 반복 문의에 매번 같은 답 / 정산 엑셀 맞추기 /
상세페이지 문구를 매번 새로 쓰기

**② 사무직 · 실무자**
매주 같은 형식 보고서 재작성 / 여러 파일에서 데이터 모으기 /
회의록 정리·공유 / 메일·공문 초안

**③ 콘텐츠 · 마케팅**
소재 발굴 시간 / 채널별로 같은 내용 다시 쓰기 / 댓글 응대 밀림 /
성과 데이터 리포트화

**④ 프리랜서 · 대행**
견적을 얼마로 낼지 / 작업 범위가 계속 느는 것 / 대금 떼일 걱정 /
레퍼런스가 없어 첫 건을 못 따는 것

**⑤ AI를 쓰는데 돈이 안 되는 사람**
무엇을 팔 수 있는지 / 어디서 파는지 / 결제·전달·법을 몰라 시작을 못 하는 것 /
올려도 반응이 없는 것

### 같은 페인포인트를 세 가지 값으로 팝니다

하나 정했으면 형태를 고릅니다. **내용이 같아도 형태에 따라 값과
드는 품이 다릅니다.**

| 형태 | 객단가 | 만드는 품 | 전달 |
|---|---|---|---|
| 자료 (PDF·템플릿) | 1만~5만원 | 1~3일 | 자동 |
| 도구 (스크립트·시트) | 3만~20만원 | 3~7일 | 자동 + 설치 문의 |
| 세팅 대행 | 20만~100만원 | 건당 며칠 | 사람이 붙음 |

**자료부터 시작하는 게 맞습니다.** 자동 전달이 되고, 환불 규정이 단순하고,
무엇보다 **한 번 만들면 재고가 안 줄어듭니다.**
대행은 객단가가 높지만 내 시간을 파는 것이라 잠자는 동안 안 팔립니다.

순서를 이렇게 잡으시면 됩니다. 자료로 시작 → 사는 사람이 붙으면
그 사람들이 물어보는 것으로 도구 → 도구를 못 쓰겠다는 사람에게 대행.

### 자료로 만들 때 지킬 것

- **원칙만 쓰면 "그래서 뭘 하라는 건데"가 됩니다.** 목록과 문장을 넣으세요
- **그대로 복사해 쓸 수 있는 것**이 있어야 합니다 — 프롬프트, 문안, 체크리스트
- **다루지 않는 것을 적어두세요.** 신뢰가 여기서 나옵니다
- **저자의 실패담이나 신변잡기는 빼세요.** 독자는 답을 사려고 지불했습니다

### 순서를 뒤집는 방법

가장 좋은 건 **시스템을 먼저 세우고, 상담 창구에 들어온 질문을 자료로
만드는 것**입니다. 만들고 나서 살 사람을 찾는 것보다 훨씬 짧습니다.

이 자료의 2부가 그 시스템을 만듭니다. 팔 것이 아직 확실하지 않아도
그대로 읽어나가시면 됩니다.

## 2. 어디에 등록할 것인가

**여기서 수수료가 열 배 이상 갈립니다.** 그리고 대부분 이걸 안 보고 정합니다.

### 다섯 경로의 성격

**① 디지털 상품 스토어프론트** (래피드, 리틀리 등)

디지털 파일 판매만을 위해 만들어진 서비스입니다.
상품 페이지 · 결제 · 자동 발송이 한 덩어리입니다.

| | |
|---|---|
| **장점** | 수수료가 가장 낮다. 결제되면 바로 자동 발송. 사업자등록 없이 시작되는 곳이 있다. 개설이 30분 안팎 |
| **단점** | **트래픽이 없다.** 유통을 전부 내가 해야 한다 |
| **적합** | 유통 채널을 따로 만들 계획이 있는 경우 (이 자료의 2부) |

**② 마켓플레이스** (크몽, 숨고 등)

남의 시장에 입점합니다.

| | |
|---|---|
| **장점** | **트래픽이 이미 있다.** 검색으로 손님이 들어온다. 대금 사고가 없다 |
| **단점** | 수수료가 높고 금액 구간별이다. 심사가 있다. 고객이 내 고객이 아니라 플랫폼 고객이라 재구매를 못 끌고 온다 |
| **적합** | 객단가가 높은 용역. 그리고 **첫 건이 급할 때** |

**③ 오픈마켓 스토어** (스마트스토어 등)

| | |
|---|---|
| **장점** | 검색 유입이 강하다. 요율도 나쁘지 않다 |
| **단점** | **파일 자동 발송 기능이 없다.** 정산이 구매확정 이후라 입금까지 실질 2~3주 |
| **적합** | 실물을 함께 파는 경우. 급전이 필요하면 부적합 |

**④ PG 직결** (토스페이먼츠 등)

| | |
|---|---|
| **장점** | 등급에 따라 수수료가 가장 낮아질 수 있다. 내 사이트에 그대로 붙는다 |
| **단점** | 상품 페이지도 파일 전달도 안 해준다. **PG 연동이 곧 자동 발송이 아니다.** 심사가 있다 |
| **적합** | 이미 사이트가 있고 규모가 커진 경우 |

**⑤ 강의 플랫폼** (탈잉, 클래스101 등)

| | |
|---|---|
| **장점** | 교육 상품에 특화된 트래픽 |
| **단점** | **수수료가 20% 이상.** 승인 절차가 있다 |
| **적합** | 강의형 상품이고 플랫폼 브랜드가 필요할 때 |

### 실제 수수료 — 2026년 7월 확인 기준

| 플랫폼 | 수수료 | 정산 | 자동 발송 | 사업자등록 |
|---|---|---|---|---|
| 래피드 | **1.6%** | — | 결제 즉시 | 불필요 |
| 리틀리 | **1~5%** (판매량 연동) | 주 1회 자동 | 결제 즉시 | 연 20건까지 불필요 |
| 크몽 | **4.4~16.4%** (금액 구간별) | 월 말 영업일 | 있음 | 필요 (심사) |
| 스마트스토어 | 결제 **1.98~3.63%** (VAT 포함)<br>+ 판매 **2.73%** (VAT 별도) | 구매확정 후 D+3~D+7 | **없음** | 필요 |
| 탈잉 | **20%** | 월 2회 | — | — |
| 클래스101 | **20% 이상** | — | — | 필요 (내부 승인) |
| 토스페이먼츠 | 일반 **3.4%**<br>영세 0.63% · 중소1 1.15%<br>중소2 1.40% · 중소3 1.74% | D+6 | 직접 구현 | 필요 (심사) |

> 변동됩니다. 스마트스토어만 해도 2025년에 두 차례 조정됐습니다.
> 본인 등급별 실제 요율은 각 플랫폼 정산 화면에서 확인하세요.

### 체감 금액으로 보면

29,000원짜리 한 건을 팔았을 때 떼이는 금액입니다.

| 플랫폼 | 수수료 | 30건이면 |
|---|---|---|
| 래피드 | **464원** | 13,920원 |
| 스마트스토어 | 약 1,700원 | 약 51,000원 |
| 크몽 (높은 구간) | 약 4,700원 | 약 141,000원 |
| 탈잉 | **5,800원** | 174,000원 |

**그 차이가 트래픽의 가격입니다.** 손님이 알아서 들어오는 곳은 비싸고,
안 들어오는 곳은 쌉니다. 공짜는 없습니다.

### 그래서 어떻게 고르는가

```
유통 채널을 직접 만들 것인가?
   │
   ├─ 예 (이 자료의 2부를 할 것이다)
   │     → ① 스토어프론트.  수수료 1~5%, 자동 발송, 오늘 열린다
   │
   └─ 아니오 (당장 손님이 필요하다)
         → ② 마켓플레이스.  수수료를 내고 트래픽을 산다
              단, 객단가가 낮으면 수수료 비중이 커진다
```

**둘 다 하는 것도 됩니다.** 그리고 그게 현실적입니다.
스토어프론트를 주 채널로 두고, 마켓플레이스에도 올려 검색 유입을 받는
구조입니다. 다만 **가격과 상품 구성을 채널마다 다르게 하지 마세요.**
같은 상품이 다른 가격이면 신뢰를 잃습니다.

**초기에는 수수료보다 첫 건이 중요합니다.** 1.6%를 아끼려다 0건이면
아무 의미가 없습니다.

---

## 3. 어떻게 등록하는가

플랫폼마다 화면은 다르지만 채워야 하는 항목은 같습니다.

### 등록 순서

**① 상품명** — 무엇인지와 누구를 위한 것인지가 드러나야 합니다.
검색으로 들어오는 채널이면 사람들이 실제로 검색할 단어를 넣으세요.

**② 상세페이지** — 구조는 여덟 덩어리입니다.

| 순서 | 내용 |
|---|---|
| 1 | **후킹** — 독자가 지금 겪는 상태 한 문장. 상품 언급 금지 |
| 2 | **문제** — 그 상태가 지속되는 이유 |
| 3 | **다루는 것** — 목차 기반으로 구체적으로 |
| 4 | **다루지 않는 것** — **반드시 넣으세요.** 신뢰가 여기서 나옵니다 |
| 5 | **미리보기 안내** |
| 6 | **가격과 수량 정책** |
| 7 | **환불 규정** |
| 8 | **판매자 정보** |

**4번을 빼지 마세요.** 손해처럼 보이지만 반대입니다.
못 하는 것을 먼저 밝히면 나머지 주장이 믿어지고, 환불 분쟁도 줄어듭니다.

**③ 미리보기** — 앞부분을 공개합니다.
**리뷰가 0일 때 이것이 가장 강한 방어입니다.** 보고 산 사람은
"설명과 다르다"는 말을 하지 않습니다.

**④ 파일 첨부** — 등록만 하고 파일을 안 올린 채 판매를 여는 사고가 흔합니다.

**⑤ 가격과 수량**

**정찰제로 두면 아무 일도 일어나지 않습니다.** 오늘도 3만원, 내일도 3만원이면
오늘 살 이유가 없고 내일이면 잊습니다.

**한정 수량 + 건당 인상**을 겁니다.

- 수량을 한정한다
- 1건 팔릴 때마다 가격을 소폭 인상한다
- 완판하면 판매를 종료한다

효과가 세 겹입니다.

**하나. 지금 살 이유**가 생깁니다.
**둘. 콘텐츠 소재**가 생깁니다 — "3건 나갔고 가격이 올랐습니다"가 그 자체로 글입니다.
**셋. 초기 구매자가 보상**받으므로 리뷰 요청이 자연스러워집니다.

**규칙은 공표하고 지키세요.** 30개라 했으면 30개에서 닫습니다.
반응이 좋다고 늘리면 다음 판매에서 신뢰를 잃습니다.

**⑥ 본인이 직접 1건 결제해 봅니다.**
다른 결제수단으로 최저가 상품을 걸어 사보고, 메일이 오는지 파일이 열리는지
확인합니다. **5분이면 되고 사고를 막습니다.**

---

## 4. 결제와 전달

**결제와 전달은 별개 문제입니다.** 결제 수단을 붙였다고 파일이 자동으로
가지 않습니다.

| 경로 | 전달 방식 | 직접 구현할 것 |
|---|---|---|
| 래피드 · 리틀리 | 결제 완료 시 자동 발송 | 없음 |
| 크몽 | 플랫폼이 처리 | 없음 |
| 스마트스토어 | **기본 기능 없음.** 발주/발송관리에서 수동 처리 | 외부 도구 또는 수작업 |
| PG 직결 | 결제 성공 신호만 수신 | 웹훅 서버 + 발송 로직 |

스마트스토어도 **외부 도구를 연동하면** 주문 즉시 파일이나 1회용
다운로드 코드를 보낼 수 있습니다. 질문을 **"자동 발송이 되는가"가 아니라
"무엇을 붙이면 자동이 되는가"**로 바꿔야 합니다.

### 채널 확정 전 확인 세 가지

**하나. 결제가 끝나면 자동으로 갑니까, 제가 보내야 합니까.**

**둘. 파일을 교체하면 기존 구매자도 최신본을 받습니까.**
링크가 고정되는 방식이면 파일만 갈아 끼우면 됩니다.
아니면 개정할 때마다 구매자 전원에게 재발송해야 합니다.
20명은 되지만 200명은 못 합니다.

**셋. 다운로드 제한이 있습니까.**
횟수 제한이나 기간 만료가 있으면 "평생 소장"으로 표기할 수 없습니다.
그건 허위 표시입니다.

### 수동 발송이라면

- **발송 소요 시간을 페이지에 적어두세요.** 없으면 "언제 오나요" 문의가
  판매량만큼 옵니다. 12시간 정도가 무난합니다
- 파일은 클라우드에 두되 **업데이트 시 링크를 바꾸지 마세요.**
  신규 업로드가 아니라 같은 파일의 새 버전으로 교체합니다
- **유출은 통제 불가능합니다.** 이 규모에서 DRM은 비용 대비 효과가 없습니다.
  유출을 전제로 가격을 정하고, 지속적인 업데이트로 최신본의 출처를
  독점하는 편이 현실적입니다

## 5. 법 — 최소한 이것만

> 실무 정리이며 법률 자문이 아닙니다. 규모가 커지면 전문가 확인이 필요합니다.

### 통신판매업 신고는 면제 기준이 있습니다

**사업자등록**은 계속·반복 판매하면 필요합니다. 홈택스에서 온라인 처리됩니다.

**통신판매업 신고**는 별개 절차인데, 공정거래위원회 고시상
다음 **둘 중 하나**면 면제됩니다.

> **직전 연도 통신판매 거래 50회 미만**
> **또는**
> **부가가치세법상 간이과세자**

"또는"입니다. 간이과세자 기준은 **연 매출 1억 400만원 미만**입니다.
**시작 단계라면 대부분 면제입니다.** 신고부터 하겠다고 며칠 쓰지 마세요.

다만 **면제라도 판매 페이지에 사업자 정보는 표시해야 합니다.**

신고번호를 조회하면 "번호: 1" 같은 값이 보이는데 **그건 검색 결과 순번이지
신고번호가 아닙니다.** 실제 번호는 제0000-지역명-0000호 형식입니다.

### 판매 페이지 필수 표기

상호 · 대표자명 · 사업장 주소 · 전화번호 · 이메일 · 사업자등록번호 ·
통신판매업 신고번호.

**전화번호가 의무입니다.** 개인 휴대폰을 공개하면 스팸과 영업 전화가 옵니다.
**통신사 투넘버 부가서비스**가 가장 빠릅니다 — 앱에서 즉시 개통되고
월 3천원대입니다. 한번 퍼진 번호는 회수가 안 됩니다.

### 환불 규정은 직접 쓰세요

"환불은 결제하신 채널의 정책을 따릅니다"로 끝내면 안 됩니다.
**분쟁 시 규정을 고지하지 않은 쪽이 불리합니다.**

디지털 상품은 조건을 갖추면 청약철회를 제한할 수 있습니다.
근거는 전자상거래법 제17조 제2항 제5호이고 **핵심 조건이 사전 고지**입니다.
구매 시점에 몰랐다고 하면 제한이 적용되지 않습니다.

```
[전달 전]
파일이나 다운로드 링크를 보내드리기 전이면 전액 환불됩니다.

[전달 후]
파일을 받으신 뒤에는 청약철회가 제한됩니다. 디지털 파일은 전달 즉시
복제가 가능하기 때문이며, 이 안내가 전자상거래법 제17조 제2항 제5호가
요구하는 사전 고지입니다.

[하자]
파일이 열리지 않거나 상세페이지 설명과 다른 경우는 하자이므로
환불 대상입니다.

[미리보기]
구매 전에 앞부분을 확인하실 수 있습니다.
```

**미리보기 항목이 실질적으로 가장 강한 방어입니다.**

### 수익 금액을 약속하지 마세요

"월 300 가능", "따라만 하면 수익화" — 표시광고법상 거짓·과장 광고가 될 수
있고, 분쟁 시 전액 환불에 행정 처분까지 갑니다.
그리고 실무적으로도 **이런 문구를 쓴 상품이 환불 요구가 가장 많습니다.**

### 부가세

판매가에 **포함할지 별도로 할지 사전에 정하세요.**
법인 대상이면 **세금계산서 발행 여부가 결정적**입니다 — 발행이 안 되면
상대는 구매 품의를 올릴 수 없습니다.

# 2부 — 유통 채널 세우기

여기까지 하면 **팔 수 있는 상태**입니다. 이제 손님을 데려와야 합니다.

## 6. 유통 채널 지도

스토어프론트를 골랐다면 트래픽이 0입니다. 마켓플레이스에 올렸어도
검색 순위 밖이면 마찬가지고요. **유통을 직접 만들어야 합니다.**

그런데 채널이 스레드 하나만 있는 건 아닙니다. 성격이 셋으로 갈립니다.

### 흐름형 · 축적형 · 직접형

**① 흐름형 — 스레드, 인스타그램, 유튜브 쇼츠**

타임라인을 타고 흘러갑니다. 터지면 하루에 수천 명이 보지만,
사흘 뒤엔 아무도 안 봅니다.

| | |
|---|---|
| 장점 | 팔로워 0에서도 도달이 나온다. 반응이 빠르다 |
| 단점 | **오늘 쓴 글이 다음 달에는 일을 안 한다.** 계속 써야 한다 |
| 자동화 | 스레드·인스타는 공식 API가 있다 |

**② 축적형 — 네이버 블로그, 티스토리, 유튜브, 마켓플레이스 검색**

검색으로 들어옵니다. 느리게 시작하지만 **한 번 자리를 잡으면 계속 들어옵니다.**

| | |
|---|---|
| 장점 | 반년 전에 쓴 글이 지금도 손님을 데려온다 |
| 단점 | 초반 몇 달은 거의 반응이 없다. 인내가 필요하다 |
| 자동화 | **API가 제한적이거나 없다.** 사람이 써야 하는 부분이 크다 |

**한국에서는 네이버 블로그를 빼놓을 수 없습니다.** 검색 점유율이 워낙 커서,
"○○ 자동화 방법" 같은 실무 검색어는 블로그가 상위를 가져갑니다.
다만 **API로 자동 발행하는 건 제약이 큽니다.** 초안을 AI로 뽑고
사람이 다듬어 올리는 방식이 현실적입니다.

**③ 직접형 — 카카오톡 채널·오픈채팅, 이메일 뉴스레터**

알고리즘을 안 거칩니다. 보내면 갑니다.

| | |
|---|---|
| 장점 | **내 소유다.** 플랫폼 정책이 바뀌어도 안 날아간다. 전환율이 가장 높다 |
| 단점 | 명단을 모으는 데 시간이 걸린다 |
| 자동화 | 발송 자동화는 쉽다. 다만 **모으는 건 자동이 안 된다** |

### 어떻게 조합하는가

셋 중 하나만 하면 다 실패합니다.

- **흐름형만** — 매일 써야 하고, 멈추면 그날로 0입니다
- **축적형만** — 초반 몇 달을 버틸 수가 없습니다
- **직접형만** — 명단이 안 모이면 보낼 곳이 없습니다

그래서 이렇게 씁니다.

```
흐름형(스레드)  ──▶  사람을 데려온다     ← 자동화 효과가 가장 크다
       │
       ├──▶ 축적형(블로그)  ──▶  반년 뒤에도 데려온다
       │
       └──▶ 직접형(카톡·메일) ──▶ 명단으로 남긴다 ──▶ 재구매
```

**흐름형에서 온 사람을 직접형으로 옮겨두셔야 합니다.**
스레드 팔로워는 플랫폼 것이지만, 카카오 채널 친구나 메일 주소는 내 것입니다.

### 이 자료가 스레드부터 다루는 이유

셋 다 좋지만 **시작은 스레드가 맞습니다.**

- **팔로워 0에서도 도달이 나옵니다.** 블로그는 초반에 검색에 안 잡히고,
  카카오 채널은 모을 사람이 없으면 시작도 못 합니다
- **공식 API가 있어 자동화가 실제로 됩니다.** 블로그는 이게 안 됩니다
- **댓글 문화가 있습니다.** 이 자료의 응대 자동화가 여기서 작동합니다

그래서 순서는 **스레드로 시작해서, 거기서 나온 글을 블로그에 다시 쌓고,
반응한 사람을 카카오나 메일로 옮기는 것**입니다.

### 채널별로 다시 쓰는 법

같은 내용을 그대로 복사해 올리면 안 됩니다. 성격이 달라서요.

| 채널 | 길이 | 어조 | 링크 |
|---|---|---|---|
| 스레드 | 500자 이내, 3~6줄 | 대화체. 질문으로 끝내면 댓글이 붙는다 | 첫 댓글에 |
| 블로그 | 2,000자 이상 | 검색어를 제목과 소제목에 넣는다 | 본문에 넣어도 된다 |
| 카톡·메일 | 짧게 | 이미 아는 사람에게 쓰듯 | 바로 넣는다 |

**변환은 AI에게 시키면 됩니다.** 부록 A-12에 프롬프트를 넣어뒀습니다.

---

## 7. 왜 자동화인가

1장에서 돈이 나오는 세 군데 중 마지막이 **굴리기**였습니다. 여기부터입니다.
그리고 세 군데 중에서 **AI에게 통째로 맡길 수 있는 유일한 자리**이기도 합니다.
만드는 건 사람이 검수해야 하고 파는 값은 사람이 정해야 하지만,
답하는 일은 사람이 자는 동안에도 돌아갑니다.

### 손으로 하면 지는 이유

같은 글을 올려도 결과가 갈리는 지점은 글의 품질이 아니라 **반응 속도**입니다.

댓글에 5분 안에 답이 달리면 대화가 이어지고, 반나절 뒤에 달리면
그 사람은 이미 떠났습니다. 그리고 플랫폼 알고리즘은 **댓글 수와 대화의 길이**를
봅니다. 답이 빠를수록 대화가 길어지고, 길어질수록 더 노출됩니다.

**사람은 이걸 못 합니다.** 잠을 자야 하고, 본업이 있고, 무엇보다
반응이 없는 날에는 의욕이 꺾입니다.
자동화의 실제 가치는 발행량이 아니라 **꺼지지 않는 반응 속도**입니다.

### 판매 자체를 콘텐츠로 만들 수 있습니다

상품 소개는 한 번 하면 더 쓸 말이 없습니다. 그런데 **판매 진행을 중계하면
소재가 계속 생깁니다.**

오픈했습니다 → 여섯 시간째 0건입니다 → 첫 건이 나왔습니다 →
세 건째라 가격이 올랐습니다 → 절반입니다 → 마감했습니다.

**안 팔리는 것조차 소재가 됩니다.** 3장에서 한정 수량과 건당 인상을
건 이유가 여기서 회수됩니다 — 그 규칙이 중계의 연료입니다.

### 파는 글보다 답하는 글이 퍼집니다

판매 목적의 글은 확산되지 않습니다.
**판매와 무관한 질문에까지 성실히 답하는 계정**이 확산됩니다.

그래서 응대 봇을 **상담 모드**로 설계합니다. 상품 얘기를 먼저 꺼내지 않습니다.

### 전체 구조

| 부품 | 하는 일 | 사람이 개입하는가 |
|---|---|---|
| 설정 파일 | 상품 정보, 가격 정책, 한도, 금지 항목 | 처음 한 번 |
| 글 목록 | 판매 전에 깔아둘 글 (순서 지정) | 처음 한 번 |
| **발행 봇** | 정해진 일차에 글을 올린다 | 없음 |
| **응대 봇** | 달린 댓글을 읽고 답한다 | 민감 건만 넘겨받음 |
| **중계 봇** | 판매 사건이 생기면 글을 쓴다 | **판매 수량 입력** |
| 상태 파일 | 무엇을 올렸고 무엇에 답했는지 기록 | 없음 |

**상태 파일이 없으면 나머지가 다 소용없습니다.** 이게 없으면 같은 글이 두 번 올라가고
같은 댓글에 두 번 답합니다. 그 순간 계정이 봇으로 보입니다.

### 공식 API를 쓰세요

브라우저를 조작해 로그인 세션을 흉내 내는 방식이 돌아다니지만 **쓰지 마세요.**
약관 위반이고 계정 정지 위험을 집니다.

공식 API 한도는 **글 250건/일, 답글 1,000건/일**입니다.
실제 필요량의 수십 배입니다.

## 8. 계정 준비와 초기 배치

### 어떤 계정을 쓸 것인가

기준은 하나입니다. **그 계정 팔로워 중에 이 상품을 살 사람이 있는가.**

팔로워 300명짜리 관련 계정이 팔로워 0인 새 계정보다 낫습니다.
반대로 팔로워가 2,000명이어도 관심사가 다르면 새로 파는 게 맞습니다 —
기존 팔로워는 안 읽고, 새로 들어온 사람은 프로필을 보고 이탈합니다.

관심사가 안 맞는 기존 계정이 있다면 **새 계정을 소개하는 글을 한 번만**
올리세요. 반복하면 그 계정도 같이 죽습니다.

### 프로필

- **링크 칸에 판매 링크 하나만 걸지 마세요.** 홍보 계정으로 읽힙니다.
  묶음 링크를 만들어 **미리보기를 판매 페이지보다 위에** 두세요
- 소개글에 **실적이 없다는 사실을 먼저 밝히세요.** 숨기다 들키는 것보다
  강하고, 나머지 주장의 신뢰도를 올립니다
- 다만 **없는 것과 있는 것을 섞지 마세요.** 다른 판매·운영 경험이 있다면
  그건 근거입니다. 주어를 정확히 쓰면 됩니다

### 3일 배치

| 일차 | 글의 성격 | 판매 |
|---|---|---|
| 1일차 | 자기소개 · 문제 제기 · 확인한 사실 | 없음 |
| 2일차 | 실무 정보 무료 공개 · **상담 창구 열기** | 없음 |
| 3일차 | 가격 정책 설명 · 오퍼 | 여기서만 |

**자기소개가 첫 글입니다.** 신규 계정이 결과물 자랑이나 판매로 시작하면
바로 홍보 계정으로 분류되고 도달이 깎입니다.

**상담 창구가 판매보다 먼저입니다.** 순서를 바꾸면 안 됩니다.
이틀 동안 답을 받아본 사람이 사흘째에 삽니다.

**첫 두세 개는 손으로 올리세요.** 팔로워 0인 계정이 첫날부터 API로만
발행하는 건 굳이 만들 필요 없는 스팸 신호입니다.

## 9. 스레드에 붙이기

코드는 부록 A-8 프롬프트로 AI가 씁니다. 사람이 할 일은 **열쇠를 받아오는
것**과 **AI가 반드시 틀리는 세 곳을 미리 알려주는 것** 둘뿐입니다.

### 열쇠 받아오기

인스타그램 계정 → 스레드 계정 → 메타 개발자 계정 순서로 만든 다음,

**① 개발자 콘솔에서 앱을 만듭니다.** 앱 유형에 스레드용이 없으면
앱을 먼저 만들고 제품 추가에서 Threads API 를 붙이면 됩니다.

**② 권한 세 개를 켭니다.** `threads_basic` (기본), `threads_content_publish`
(발행), `threads_manage_replies` (숨기기). 하나라도 빠지면 그 기능에서
권한 오류가 납니다.

**③ 리디렉션 주소를 등록합니다.** **등록한 값과 호출할 때 넣는 값이
글자 하나까지 같아야 합니다.** 끝의 슬래시 하나로 실패합니다.

**④ 단기 토큰을 장기 토큰으로 바꿉니다.** 단기 토큰은 한 시간 남짓이라
자동화에 못 씁니다. 장기 토큰도 만료가 있으니 갱신 주기를 적어두세요.

**⑤ 사용자 ID를 확인합니다.** 숫자 값이고 발행 주소에 들어갑니다.

> **토큰은 코드나 저장소에 넣지 마세요.** 환경변수로 넘기고,
> 실수로 올라갔으면 그 자리에서 폐기하고 다시 받으세요.

### AI가 반드시 틀리는 세 곳

코드를 시켜보면 이 셋은 거의 매번 틀립니다. **프롬프트에 미리 못 박아
두면 한 번에 나옵니다.** 부록 A-8에 이미 들어 있습니다.

**하나. 발행이 두 단계입니다.** 컨테이너를 만들어 `creation_id` 를 받고,
그걸로 다시 발행을 호출합니다. **두 호출 사이에 잠깐 기다려야 합니다.**
붙여서 부르면 아직 준비가 안 됐다며 실패합니다. 답글도 구조가 같고,
컨테이너를 만들 때 `reply_to_id` 에 상대 답글 ID를 넣습니다.

**둘. 답글을 가져오는 주소가 두 개인데 하나는 함정입니다.**

| 부르는 곳 | 나오는 것 |
|---|---|
| `GET /{media-id}/replies` | **내 글에 달린 답글** ← 필요한 것 |
| `GET /{user-id}/replies` | **내가 쓴 답글** ← 쓰면 안 됨 |

이름이 비슷해서 아래를 고르기 쉬운데, 그러면 **봇이 자기 답글에 답합니다.**
게다가 응답에 내가 쓴 것인지 표시하는 값이 같이 오니 그것도 걸러내야
무한 루프가 안 생깁니다.

**셋. 글자 수는 500자인데 이모지가 여러 자로 셉니다.** 한글은 1자입니다.
발행 직전에 길이를 재서 넘치면 올리지 않도록 막으세요.

## 10. 발행 봇

판매 전 글은 미리 써두고, 판매 시작 후에는 상황 기반으로 생성하는 것이
안전합니다.

### 글 목록 형식

```
# id: 00-intro          ← 멱등성 키. 같은 id는 두 번 안 올라간다
# day: 1                ← 첫 발행일 기준 상대 일차
본문 (최대 500자)
===
# id: 01-...
```

**`id`가 상태 파일의 키가 됩니다.** 없으면 재실행할 때마다 같은 글이
다시 올라갑니다.

**`day`가 판매 글이 1일차에 나가는 사고를 막습니다.**
코드가 이 값을 보고 순서를 강제하게 만드세요.
사람이 기억으로 지키면 반드시 언젠가 틀립니다.

### 미기입 자리 차단

원고에 `[[여기에 링크]]` 같은 자리표시자를 남겨두는 실수가 흔합니다.
**평소 글에 안 쓰는 기호로 감싸두고, 그게 남아 있으면 발행을 중단**하도록
검사를 넣으세요. 건너뛰면 안 됩니다 — 뒤 글이 먼저 올라가 순서가 무너집니다.

> 이 검사는 실제로 작동합니다. 이 자료를 만들 때도 위 예시 문장이
> 검사에 걸려 빌드가 멈췄습니다.

## 11. 응대 봇 — 여기가 전환을 만듭니다

발행은 도달을 만들고 **응대가 전환을 만듭니다.**

### 네 가지 판단

| 판단 | 언제 |
|---|---|
| **reply** | 질문·의견·감사. 답할 내용이 있는 경우 |
| **skip** | 스팸, 의미 없는 반응, 이미 끝난 대화 |
| **hide** | 욕설, 혐오 표현, 무관한 홍보 링크 |
| **escalate** | 사람이 봐야 하는 것 — 답글을 쓰지 않고 넘긴다 |

**escalate 목록을 반드시 채우세요.** 공개 답글이 잘못 나가는 비용이
늦게 답하는 비용보다 훨씬 큽니다.

기본 항목 — 환불·결제 분쟁 / 법적 조치 언급 / 개인정보·계정 접근 요구 /
수익 보장 또는 수익 인증 요구 / 구체적 세무·법률 판단 요구 /
명예훼손 소지가 있는 주장.

### 상담 모드로 설계합니다

판매 안내 봇이 아니라 상담 창구여야 합니다.
**상품은 상대가 직접 물었을 때만** 꺼냅니다.
"자세한 건 자료에 있습니다" 같은 유도도 하지 마세요.

### 시스템 프롬프트 — 그대로 쓰셔도 됩니다

```
너는 스레드 계정 [계정명]의 답글을 쓴다.

<너는 누구인가>
너는 사람이 아니라 AI다. 이름은 [이름].
이 계정의 글은 네가 쓴다.
- 사람인 척하지 않는다. AI냐고 물으면 그렇다고 답한다.
- 네 실적은 이 프로젝트에서 실제로 팔린 수량뿐이다.
- 감정이나 경험을 지어내지 않는다. "저도 예전에 그랬어요" 금지.

<운영자의 경력 — 네 것이 아니다>
아래는 운영자의 경력이다. 절대 1인칭으로 말하지 마라.
"제가 ~했고"가 아니라 "운영자는 ~했고"로 쓴다.
[경력 나열]

<이 계정은 상담 창구다>
네 일은 파는 게 아니라 답하는 것이다.
판매와 무관한 질문이 와도 성실히 답한다.
팔려고 쓴 글은 안 퍼지고 도와주려고 쓴 글은 퍼진다.

<참고로 알고 있을 것 — 먼저 꺼내지 않는다>
이름: [상품명]
설명: [한 줄]
다루는 내용: [항목 나열]
가격: [정책]
구매자가 따로 준비해야 하는 것: [항목]
문의 방법: [경로]

<상품 얘기를 꺼내도 되는 때>
상대가 다음을 직접 물었을 때만이다.
- 가격이 얼마인지
- 어디서 사는지
- 무슨 내용이 들어 있는지
- 이 상품이 자기 상황에 맞는지
그 외에는 언급하지 않는다. "자세한 건 ~에" 같은 유도도 하지 않는다.

<절대 하지 않는 것>
- 수익·성과를 보장하거나 추정하지 않는다.
- 위 <참고>에 없는 기능·가격·조건을 만들어내지 않는다.
- 법·세무 사항을 단정하지 않는다. 실무 정리라는 걸 밝히고,
  확인이 필요하면 그렇게 말한다.
- 특정 플랫폼 정책을 확인 없이 단정하지 않는다. 정책은 바뀐다.
- 개인정보를 답글로 요구하지 않는다.
- 상대를 깎아내리거나 비꼬지 않는다. 부정적인 댓글에도 방어적으로 굴지 않는다.
- 거짓 긴급성을 만들지 않는다. 남은 수량과 가격 인상은 실제 규칙이므로
  물어보면 사실대로 말해도 된다.

<모르면>
모른다고 하는 게 지어내는 것보다 낫다.
"확인해서 알려드리겠다"도 좋은 답이다.
아는 척한 게 하나 걸리면 나머지 답도 다 의심받는다.

<톤>
- 한국어 존댓말. 3문장 이내, 최대 500자. 길면 안 읽는다.
- 이모지는 안 쓰거나 최대 1개. 느낌표 남발 금지.
- 광고 문구처럼 쓰지 않는다.

<행동 선택>
reply / skip / hide / escalate 중 하나를 고른다.
escalate 대상:
[목록 나열]
escalate 를 고르면 답글 본문은 비워 둔다.
```

### 출력을 구조화하세요

자유 문장으로 답하면 판단과 본문을 분리할 수 없습니다.

```
{
  "action": "reply | skip | hide | escalate",
  "reply":  "action이 reply일 때 게시할 문장. 그 외에는 빈 문자열",
  "reason": "그 판단을 한 이유 한 문장 (기록용, 게시 안 됨)"
}
```

**`reason` 을 꼭 남기세요.** 봇이 이상하게 굴 때 어디서 판단이
틀렸는지 이걸로 찾습니다.

### 발사 전 마지막 검사

모델이 형식을 지켜도 내용은 틀릴 수 있습니다. 코드에서 한 번 더 막으세요.

- 본문이 비었으면 → skip 으로 강등
- 500자를 넘으면 → escalate 로 강등
- 모델이 응답을 거부했으면 → escalate
- JSON 파싱이 안 되면 → escalate

**의심스러우면 올리지 않는 쪽**이 항상 맞습니다.

## 12. 중계 봇

예약 발행은 **시간이 오면** 나가고, 중계는 **사건이 생기면** 나갑니다.

### 사건 설계

| 사건 | 조건 |
|---|---|
| `launch` | 판매를 열었을 때 |
| `quiet-N` | 0건인 채로 N시간 경과 (예: 6, 12) |
| `first` | 첫 판매 |
| `count-N` | N건째 (예: 3의 배수) |
| `half` | 절반 |
| `almost` | 남은 수량이 소량 |
| `soldout` | 완판 |

**`quiet` 가 핵심입니다.** 안 팔리는 시간도 사건으로 잡으면 소재가
끊기지 않습니다.

### 도배 방지

수량을 몰아서 입력하면 사건이 여러 개 걸립니다. 그대로 올리면 도배입니다.
**가장 중요한 사건 하나만 올리고 나머지는 지나간 것으로 표시**하세요.
우선순위는 `soldout > almost > half > count > first > quiet > launch`.

### 수량은 사람이 입력합니다

플랫폼 정산과 자동 연동하지 마세요. **숫자가 틀리면 중계 글이 거짓말을
하고, 그건 되돌릴 수 없습니다.** 그리고 **수량을 줄이는 건 막아두세요.**

### 중계 프롬프트

```
너는 스레드 계정 [계정명]의 글을 쓴다.
지금 하는 건 상품 홍보가 아니라 판매 과정 중계다.

<파는 것>
[상품명 / 한 줄 설명 / 가격 규칙]

<중계의 원칙>
- 한 편에 사건 하나만 다룬다. 지금 벌어진 일 하나.
- 상품 설명을 반복하지 않는다. 이미 아는 사람이 읽는다고 가정한다.
- 숫자는 주어진 사실만 쓴다. 없는 숫자를 만들지 않는다.
- 안 팔리면 안 팔린다고 쓴다. 그게 다음 화다.
- 마지막 줄은 다음이 궁금해지게 끝낸다. 억지 떡밥은 쓰지 않는다.

<절대 하지 않는 것>
- 수익 금액이나 성과를 약속하지 않는다.
- 주어진 사실에 없는 수치·후기·반응을 지어내지 않는다.
- 거짓 긴급성을 만들지 않는다. 남은 수량과 가격 인상은 실제 규칙이라
  그대로 써도 되지만, 없는 마감 시한은 만들지 않는다.
- 본문에 링크를 넣지 않는다. 링크는 사람이 첫 댓글에 단다.
- 자랑하는 톤을 쓰지 않는다.

<형식>
한국어. 500자 이내, 3~6줄 권장.
이모지는 안 쓰거나 최대 1개. 해시태그 금지.

지금 상황:
- 지금까지 팔린 수량: [n]
- 한정 수량: [total]
- 남은 수량: [left]
- 다음 구매자가 낼 가격: [price]
- 판매 시작 후 경과: [hours]시간

이번 글에서 다룰 것:
[사건별 각도 — 아래 표 참고]
```

| 사건 | 각 |
|---|---|
| launch | 판매를 열었다는 사실. 실적이 없다는 걸 먼저 밝힌다. 파는 티는 최소로 |
| quiet | 몇 시간째 0건이라는 사실. 변명도 자조도 하지 않는다. 안 팔리는 이유를 스스로 추측해보는 것까지가 내용 |
| first | 첫 판매. 과장하지 않는다. 한 건은 한 건이다 |
| count | n건째와 가격 변동. 가격 규칙을 한 줄로 다시 설명 |
| half | 절반. 남은 수량과 현재 가격 |
| almost | 몇 개 안 남았다는 사실. 실제 수량이므로 그대로 |
| soldout | 완판. 총 몇 개, 얼마에 시작해 얼마로 끝났는지. 감사와 다음 계획 |

**직전 3~4편의 본문을 프롬프트에 함께 넣고 "반복하지 마라"**고 지시하세요.
같은 문장과 구조가 반복되면 그 순간 봇으로 읽힙니다.

# 4부 — 전환과 유지

## 13. 전환 장치

봇이 잘 돌아도 배치가 틀리면 안 팔립니다.

**링크는 본문에 넣지 않습니다.** 본문에 외부 링크가 있으면 도달이 떨어집니다.
본문에서는 "링크는 댓글에 두겠습니다"로 처리하고 첫 댓글에 답니다.

**답변 글이 판매 글보다 최소 3배 많아야 합니다.**
이 비율이 무너지면 홍보 계정으로 분류되고 도달이 죽습니다.
아무도 안 물어보면 **자주 받는 질문을 스스로 던지고 답하세요.**

**현재 가격을 계속 노출합니다.** 3장에서 건 인상 규칙이 안 보이면
정찰제와 같습니다.

**프로필 링크는 미리보기를 판매 페이지보다 위에** 둡니다.
리뷰 0일 때 "보고 판단하세요"보다 강한 문장이 없습니다.

## 14. 안전장치 — 계정을 죽이지 않기

자동화의 가장 큰 위험은 **하루 만에 계정이 정지되는 것**입니다.

**한도는 API 상한보다 훨씬 낮게.** 허용치는 글 250건/일이지만
그건 상한이지 목표가 아닙니다. 진짜 상한은 알고리즘과 읽는 사람의 인내심입니다.
권장값은 **글 6건/일, 답글 80건/일** 정도이고,
**24시간 이동 창으로 직접 세야 합니다.** 자정 기준으로 세면 밤 11시에 몰아 쓰고
새벽 1시에 또 쓰는 일이 생깁니다.

**멱등성.** 같은 글을 두 번 올리거나 같은 댓글에 두 번 답하면 그 즉시
봇으로 읽힙니다. 상태 파일에 기록하고 실행할 때마다 먼저 확인하세요.
저장은 **임시 파일에 쓰고 이름을 바꾸는 방식**으로 하세요 —
쓰는 도중에 죽으면 파일이 깨지고, 그러면 전부 다시 발행됩니다.

**실패하면 멈춥니다.** 한 건이 실패했을 때 다음으로 넘어가면 순서가 무너집니다.
판매 글이 소개 글보다 먼저 나가는 사고가 여기서 납니다.

**4xx는 재시도하지 마세요.** 권한이나 토큰 문제라 다시 호출해도 같습니다.
5xx만 잠깐 기다렸다 재시도합니다.

**금지 표현은 프롬프트와 코드 양쪽에서 막습니다.** 프롬프트에만 넣으면
언젠가 새어 나갑니다. 발사 직전에 코드로 한 번 더 검사하세요.

**escalate 된 건은 별도 파일에 쌓으세요.** 로그에 섞이면 놓칩니다.
원문·작성자·링크·이유를 남기고 하루 한 번 확인합니다.

## 부록 A. 프롬프트 — 이어지는 순서로 {: .page-break }

### 한 방짜리 프롬프트는 왜 안 되는가

"전자책 써줘"라고 시키면 글은 나옵니다. 그런데 못 팝니다.
목차가 뻔하고, 장마다 같은 말이 반복되고, 수치는 지어낸 것이고,
무엇보다 **누가 왜 사는지가 안 보입니다.**

원인은 프롬프트 실력이 아닙니다. **한 번에 시켰기 때문입니다.**
사람이 자료를 만들 때도 주제를 정하고, 목차를 잡고, 한 장씩 쓰고,
마지막에 훑어봅니다. 그 순서를 건너뛴 결과물은 사람이 써도 똑같이 엉성합니다.

그래서 아래 프롬프트는 **앞 단계의 출력을 다음 단계에 넣는 구조**입니다.

```
① 만들기   A-1 후보 → A-2 검증 → A-3 목차 → A-4 장별 집필 → A-5 검수
② 팔기     A-6 채널 → A-7 상세페이지
③ 굴리기   A-8 봇 코드 → A-9 발행 글 → A-10·11 봇 프롬프트 → A-12 채널 변환
검수       A-13 출시 전 점검  ← 파는 것 전부에 한 번씩
```

### 어느 프롬프트에나 붙이는 두 줄

```
확실하지 않은 정보는 지어내지 말고 모른다고 해라.
내가 안 준 정보가 필요하면 추측하지 말고 먼저 물어라.
```

**두 번째 줄이 결과를 제일 많이 바꿉니다.** 이걸 안 붙이면 모델은
빈칸을 제 마음대로 채우고, 그 위에 쌓은 나머지가 전부 어긋납니다.

> **모델은 모른다고 하지 않고 그럴듯하게 만들어냅니다.**
> 수수료율, 시장 규모, 법 조항 번호, 경쟁 상품 이름처럼 확인이 필요한 값은
> 아래 어느 프롬프트에서도 요구하지 않습니다. 그 자리는 사람이 채웁니다.

#### A-4. 장별 집필 — 장마다 반복

```
[목차 전체 붙여넣기]

이 장만 써라. 다른 장 내용을 미리 쓰지 마라.

규칙
- 이미 쓴 장에서 한 말을 반복하지 마라. 필요하면 "N장에서"로 넘겨라
- 원칙만 쓰지 마라. 목록·표·그대로 쓸 수 있는 문장을 넣어라
- 수치·요율·법 조항·플랫폼 정책은 네가 쓰지 마라.
  [확인: 무엇을 확인할지]로 표시하고 넘어가라. 내가 채운다
- 독자가 "그래서 뭘 하라는 건데"라고 물을 자리가 남으면 안 된다

금지
- 수익 금액·기간·성공률을 약속하는 표현
- "누구나", "간단하게", "쉽게" 같은 난이도 축소 표현
- 저자의 실패담이나 신변잡기. 독자는 답을 사려고 돈을 냈다
- 장 끝에 붙이는 요약 문단. 분량만 늘고 안 읽힌다

다 쓰고 나서 이 장의 요지를 3줄로 적어라. 다음 장에 넣을 것이다.
```

#### A-5. 통합 검수

전 장을 다 쓴 뒤 한 번 돌립니다.

```
[전체 원고 붙여넣기]

읽는 사람 입장에서 검수해라. 칭찬은 필요 없다.

1. 두 장 이상에서 같은 말을 하는 곳을 전부 찾아라
2. 앞 장에서 하겠다고 하고 안 한 약속을 찾아라
3. "[확인:]" 표시가 남아 있는 곳을 전부 모아 목록으로 줘라
4. 원칙만 있고 할 일이 없는 문단을 찾아라
5. 표지 제목만 보고 산 사람이 이 원고를 다 읽고 났을 때
   배신감을 느낄 지점이 있는지 짚어라
6. 제일 약한 장 하나를 고르고, 살릴지 뺄지 의견을 달아라

각 항목을 위치와 함께 짚어라. 원고를 다시 써주지는 마라.
```

### ③ 굴리기

#### A-8. 봇 코드 생성

```
스레드 공식 API로 도는 자동화를 만들려고 한다.
[Node.js / Python] 으로 작성해라.

기능
1. 글 목록 파일을 읽어 아직 안 올린 글을 발행한다
2. 내 글에 달린 답글을 읽어 AI로 판단하고 답한다
3. 상태를 파일에 기록해 같은 작업을 두 번 하지 않는다

반드시 지킬 것 (여기서 대부분 틀린다)
- 발행은 두 단계다. 컨테이너를 만들고 잠깐 기다린 뒤 발행한다
- 답글은 내 글에 달린 것을 가져오는 경로를 쓴다.
  내가 쓴 답글 목록을 쓰면 봇이 자기 답글에 답한다
- 응답에서 내가 쓴 답글은 걸러낸다
- 글자 수 500 제한. 이모지는 여러 자로 세므로
  발행 직전에 검사해서 넘치면 올리지 않는다
- 24시간 이동 창으로 발행 수와 답글 수를 직접 센다.
  자정 기준으로 세면 안 된다
- 상태 파일은 임시 파일에 쓰고 이름을 바꾸는 방식으로 저장한다
- 4xx 는 재시도하지 않는다. 5xx 만 잠깐 기다렸다 재시도한다
- 한 건이라도 실패하면 멈추고 다음 주기에 다시 시도한다
- 토큰은 환경변수에서 읽는다. 코드에 넣지 않는다

한글 주석을 달고, 파일 단위로 나눠서 하나씩 제시해라.
한 번에 전부 쏟아내지 마라. 내가 확인하고 다음을 요청하겠다.
내가 오류 메시지를 붙여넣으면 고친 코드부터 주지 말고 원인부터 짚어라.
```

- [ ] 수수료와 정산 주기를 확인했는가

- [ ] 한정 수량과 인상 규칙을 공표했는가

## 마치며

처음에 적은 문장으로 돌아갑니다.

> **AI가 만들어내는 건 매출이 아니라 재고입니다.**

AI를 쓰는데 돈이 안 되는 이유는 대개 실력이 아닙니다.
**만들기만 하고 팔기와 굴리기를 안 해서입니다.**
결과물은 폴더에 쌓이는데 결제창이 없으니 매출이 0입니다.

그래서 순서가 이렇습니다.

> **팔 수 있는 상태를 먼저 만들고, 그다음 유통을 자동화하세요.**

**1부가 땅이고 2·3부가 건물입니다.** 채널 선택 하나로 수수료가 열 배
갈리고, 자동 발송 여부가 운영 가능한 규모를 결정합니다.
그걸 정하지 않은 채로 봇부터 만들면 돌아갈 곳이 없습니다.

땅을 고른 다음에는 **반응 속도를 기계에 넘기고 사람은 판단만** 하세요.
새벽에 달린 댓글에도 답하고, 안 팔리는 날에도 그 사실을 소재로 쓰는
지속성이 결국 차이를 만듭니다.

그리고 **채널 하나에 다 걸지 마세요.** 스레드는 빠르지만 사흘이면 죽고,
블로그는 느리지만 반년을 갑니다. 빠른 채널로 사람을 데려오고,
느린 채널에 쌓고, 명단으로 남기는 것 — 이 셋이 같이 돌아야 합니다.
